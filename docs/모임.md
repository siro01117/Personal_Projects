# 모임 — 설계서 v2

**약속을 관리하는 곳.** 누구와 · 언제 · 어디서 만나는지 적어 두고, 시간이 안 정해졌으면 맞추고, 정해지면 일정으로 넘기고, 누가 왔는지 남긴다.
시간 맞추기(웬투밋)는 그 안의 기능 하나다 — v1 은 시간 맞추기만 설계했다가 2026-10-02 피드백으로 넓혔다.
기준 문서: 이 문서. 일정 쪽 규칙은 `docs/일정.md`, 할 일은 `docs/플래너.md`, 공개 링크 방식은 `docs/보고서-서랍.md` 5장 "공유".

## 0. 정해진 것 (2026-10-02)

- 다음 모듈은 모임. 프로젝트 관리(질문지 · 유저플로우 · IA 묶음)는 그다음
- **모임 = 만남 한 번**이 기본 단위. 원하면 **묶음**(예: APPTIVE 1팀, 스터디)에 넣는다 — 묶음을 고르면 사람들이 채워지고, 묶음별로 지난 만남이 쌓인다. 묶음 없는 한 번짜리 약속도 된다
- 기록은 가볍게: 약속 관리용이라 내용으로 할 것은 많지 않다. **메모 한 칸 + 참석 여부**. 회의록 · 보고서 연결은 안 넣는다
- 모임에서 **할 일**이 나올 수 있고(플래너로), **다음 모임**이 또 나올 수 있다(같은 사람들로)
- 나중에 프로젝트 모듈이 생기면 동아리 팀 같은 것은 프로젝트가 위에 서고 **거기서 모임이 파생**된다 → 지금은 구멍만(`origin_kind = 'project'`)
- **남은 로그인 없이** 링크로 들어온다. 이름 + **핀번호**. 핀을 잊으면 **주최자가 지워 주고** 다시 만들어 들어온다
- 같은 서비스 가입자끼리의 친구 추가는 나중 — 가입자가 아닌 경우가 훨씬 많으므로 남(게스트) 흐름이 먼저다. 사람 줄에 구멍만(`user_id`)
- **내 되는 시간은 일정에서 자동으로 칠해지고, 그 모임용으로 내가 고친다**
- 시간을 정하면 **일정에 약속으로** 들어간다 (`ez_events.origin_kind = 'meet'` — 0006 에 구멍이 이미 있다)
- 1차에서 뺀 것: 장소 투표 · 회의록 · 알림 · 캘린더 연동 · 댓글 · 정산 · 친구
- 미니멀 1차(설명 문구 · 라벨 · 상태 칩 없음), 포인트 색은 키위 하나, 모든 화면에서 밝기 전환, 한글은 띄어쓰기에서만 줄바꿈, 누르면 보기 · 고치기는 '수정' 뒤, 거르지 말고 정렬

## 1. 무엇이 다른가

| | 웬투밋 · 캘린더 | 여기 |
|---|---|---|
| 약속의 일생 | 시간 맞추기에서 끝나고, 캘린더에 따로 적고, 누가 왔는지는 어디에도 없다 | 한 줄기: 만들기 → (맞추기) → 정하기 → 일정 → 참석 → 할 일 · 다음 모임 |
| 내 되는 시간 | 매번 손으로 칠함 | 일정(수업 · 근무 · 이동 · 준비)을 빼고 자동, 필요하면 고침 |
| 남에게 보이는 것 | — | 되는 칸만. **일정 제목 · 장소는 절대 안 나간다** |
| 같은 사람들과 또 | 매번 새로 | 묶음을 고르면 사람들이 채워지고, 지난 만남이 묶음에 쌓인다 |
| 결과 읽기 | 격자를 눈으로 훑음 | 모임 길이에 맞춰 "가장 많이 되는 시간" 을 뽑아 줌 |

## 2. 데이터

### `ez_circles` 묶음

| 칸 | 규칙 |
|---|---|
| `id` `owner` `created_at` `updated_at` `deleted_at` | 다른 `ez_` 테이블과 같다. RLS `owner = auth.uid()` |
| `name` | 1~30자, 내 것 안에서 겹침 없음 |
| `role_id` → `ez_roles` (null 가능) | 플래너의 역할(대학 · 강사 · 개인 · 동아리). 묶음의 모임 · 거기서 나온 할 일이 이 역할을 물려받는다 |
| `members` text[] | 늘 오는 사람 이름들, 0~50, 각 1~20자, 겹침 없음. 나는 안 적는다 |
| `origin_kind` `origin_id` | 프로젝트 구멍(지금은 늘 null) |

- 묶음 30개까지. 묶음을 지워도 모임은 남는다(`circle_id` 만 빈다)

### `ez_meets` 모임 (만남 한 번)

| 칸 | 규칙 |
|---|---|
| `id` `owner` `version` `created_at` `updated_at` `deleted_at` | 같다 |
| `title` | 1~60자 |
| `note` | ≤ 2,000자. 안건이든 뒷이야기든 한 칸. 공개 페이지에 **안 나간다**(내 메모) |
| `circle_id` → `ez_circles` on delete set null | |
| `place_id` → `ez_places` on delete set null · `place_text` (≤ 60자) | 내 지점에서 고르거나 글자로. 공개 페이지에는 지점 **이름만** |
| `meet_date` `start_min` `end_min` | **정해진 시간.** 셋 다 있거나 셋 다 없음(= 아직 안 정함) |
| `event_id` → `ez_events` on delete set null | 정하면서 만든 일정 |
| `poll` jsonb (null 가능) | 시간 맞추기 설정. 없으면 맞추기를 안 쓰는 모임. `{dates:[…], day_from, day_to, duration_min}` — 후보 날짜 1~31개(겹침 없음, 오름차순), 하루 범위는 30분 단위 `0 ≤ from < to ≤ 1440`, 길이 30~480(30분 단위, 기본 60) |
| `token` | 공개 링크 열쇠, 추측 불가 22자. **링크를 켤 때** 생기고 끄면 지워진다(다시 켜면 새 열쇠 — 보고서 공유와 같다) |
| `origin_kind` `origin_id` | 프로젝트 구멍 |

- 상태는 칸에서 읽는다(따로 안 적는다): 시간 없음 + `poll` 있음 = **맞추는 중** · 시간 없음 + `poll` 없음 = **미정** · 시간 있고 아직 안 지남 = **다가옴** · 지남 = **지난 모임**
- 칸 하나는 **30분** 고정. 자정을 넘기는 범위는 없다. 시간대는 한국 시간 하나

### `ez_meet_people` 사람

모임마다 사람 한 줄. 주최자가 미리 넣은 사람도, 링크로 들어와 스스로 이름을 적은 사람도 같은 줄이다.

| 칸 | 규칙 |
|---|---|
| `id` `meet_id` (on delete cascade) `created_at` `updated_at` | |
| `name` | 1~20자. 한 모임 안에서 대소문자 · 공백 무시하고 겹침 없음 |
| `is_owner` | 내 줄. 모임당 정확히 1개, 모임을 만들 때 같이 생긴다 |
| `user_id` | 가입자 구멍(지금은 내 줄만 채워진다) |
| `pin_hash` `pin_salt` | 핀번호(숫자 4~6자리)의 `sha256(salt ‖ pin)`. 없으면 아직 안 들어온 사람. **어떤 함수도 이 값을 밖으로 안 준다** |
| `pin_fails` `pin_locked_until` | 틀린 횟수. 5번 틀리면 10분 잠김 |
| `cells` jsonb | `{"2026-10-05":[540,570,600], …}` — 날짜별 **되는 칸의 시작 분**. 없으면 아직 안 칠함 |
| `auto` | 내 줄만: 일정에서 자동으로 채운 상태인지 (3장) |
| `attend` | `yes` · `no` · null. 정해지기 전에는 안 쓴다. 정해진 뒤에는 "온다 / 못 온다", 지난 뒤에는 "왔다 / 안 왔다" — 같은 칸이다 |

- 한 모임에 50명까지
- RLS: 주최자만 직접 읽고 쓴다. **남은 테이블에 직접 닿지 못하고** 아래 함수로만 드나든다

### 다른 테이블에 닿는 것

- `ez_events`: 정하면 한 건 생김(`origin_kind='meet'`, `origin_id`). 묶음의 역할은 일정에는 아직 안 붙는다(일정에 역할이 없다)
- `ez_tasks`: 모임에서 만든 할 일은 `origin_kind='meet'`, `origin_id`, 묶음의 역할과 모임의 지점을 물려받는다. 플래너에서는 보통 할 일과 똑같이 다룬다

### DB 함수

| 함수 | 누가 | 하는 일 |
|---|---|---|
| `ez_meet_public(token)` | anon | 공개 페이지가 읽는 것: 제목 · 지점 이름 · 정해진 시간 · 맞추기 설정 · 사람들(이름, 칸, 주최자 여부, 참석, **핀이 있는지 여부만**). `owner` · `id` · 메모 · 일정 내용 · 핀 값은 안 준다. 없는 열쇠 · 지운 모임은 빈 결과 |
| `ez_meet_enter(token, name, pin)` | anon | 들어오기. 그 이름이 없으면 새 줄 + 핀 설정, 있는데 핀이 없으면(미리 넣어 둔 사람 · 지워 준 사람) 핀 설정, 있고 핀이 있으면 확인. 틀리면 횟수를 올리고 5번째에 잠근다 |
| `ez_meet_answer(token, name, pin, cells)` | anon | 되는 칸 저장. 핀 확인 + 맞추는 중인지 + 칸이 30분 단위이고 후보 날짜 · 범위 안. 결과로 전체를 다시 준다 |
| `ez_meet_rsvp(token, name, pin, attend)` | anon | 정해진 모임에 온다 / 못 온다 |
| `ez_meet_decide(id, base_version, date, start, end)` | 주최자 | 한 번에: 일정 한 건 만들기 + 모임에 시간 · `event_id` 적기. 이미 일정이 있으면 그 일정을 옮긴다 |
| `ez_meet_reopen(id, base_version)` | 주최자 | 정한 시간을 비우고 딸린 일정을 지운다 |

- 주최자 쪽 만들기 · 고치기 · 사람 넣고 빼기 · **핀 지우기**(`pin_hash` 를 비움) · 참석 표시 · 내 칸 저장은 RLS 아래 테이블에 직접. MCP 용 `p_as` 는 MCP 가 부르는 함수에만
- anon 이 쓰는 함수이므로 크기를 전부 막는다: 이름 20자 · 50명 · 칸 수는 `날짜 31 × 하루 48` 상한. 핀은 4~6자리 숫자만
- 핀은 약한 열쇠다(4자리 = 1만 가지). 막는 것은 **잠금**(5번 · 10분)과 **링크 열쇠**(22자, 모르면 시도조차 못 함) 둘이다. 지키는 것이 "남이 내 되는 시간을 못 바꾸게" 정도라 이걸로 충분하다고 본다

## 3. 계산 (`lib/meet/` — 순수 함수, 웹과 MCP 가 같이 쓴다)

**내 되는 시간**
- 후보 날짜마다 `lib/schedule` 의 `planRange` → `freeSlots` 로 빈 시간을 구해, **통째로 비는 30분 칸**만 되는 칸으로 친다. 일정에 딸린 준비 · 이동도 바쁜 시간이다. 종일 일정은 바쁜 것으로 안 친다(`busyOf` 그대로)
- 내 줄이 `auto = true` 인 동안은 **내가 모임 화면을 열 때마다 다시 계산해 저장**한다(서버가 없으므로 "열 때" 가 갱신 시점 — 플래너의 반복과 같은 방식)
- **그 모임용으로 고치기**: '수정' 을 누르고 칸을 칠하거나 지우면 `auto = false` — 그 뒤로는 안 건드린다. 일정은 안 바뀐다(이 모임에서만 다르게 보이는 것). '일정에 맞추기' 로 되돌린다
- 이 모임 자체로 가는 이동시간은 1차에서 안 본다(정한 뒤 일정이 이동 블록을 만들고, 겹치면 일정 화면이 알려 준다)

**겹침**: 칸마다 되는 사람 수. 색 진하기는 `되는 수 ÷ 칠한 사람 수` 를 키위 4단으로

**추천 시간**
- 길이만큼 이어진 칸 묶음(30분씩 밀어 가며)마다 **끝까지 다 되는 사람 수**
- 차례: 사람 수 많은 순 → 내가 되는 것 먼저 → 이른 날짜 · 이른 시각. 겹치는 묶음은 가장 이른 것 하나만(10:00, 10:30, 11:00 이 줄줄이 나오지 않게)
- 5개까지. 0명짜리 · 지난 시각은 뺀다

## 4. 약속의 흐름

1. **만들기** — 제목만 있으면 된다. 묶음을 고르면 사람들이 채워진다. 시간은 셋 중 하나:
   - 이미 안다 → 날짜 · 시각을 적는다 → 바로 일정에 들어간다
   - 맞춰야 한다 → 후보 날짜를 고른다(맞추기 켜짐) → 링크를 보낸다
   - 아직 모른다 → 비워 둔다
2. **맞추기** — 남들이 링크로 들어와 칠한다. 나는 자동으로 칠해져 있다
3. **정하기** — 추천 시간이나 격자의 칸을 눌러 보고 → **'이 시간으로'** 를 한 번 더(누르면 보기만). 일정이 생기고 맞추기는 닫힌다. 링크는 살아 있어서 남들은 정해진 시간을 보고 **온다 / 못 온다**를 누를 수 있다
4. **지난 뒤** — 참석을 고친다(왔다 / 안 왔다). 메모를 적는다
5. **파생**
   - **할 일**: 모임 화면에서 바로 적는다 → 플래너의 할 일(모임에서 온 것). 모임 화면에는 그 모임에서 나온 할 일이 줄로 보이고 끝냄 체크가 된다
   - **다음 모임**: 같은 묶음 · 사람 · 지점 · 제목으로 새 모임을 연다(시간만 비어 있음)

- 정한 뒤 **다시 열기**: 시간을 비우고 딸린 일정을 지운다. 칠한 것은 남아 있다
- 일정 화면에서 그 약속을 지우면 모임은 시간이 정해진 채 `event_id` 만 빈다 → 모임 화면에 '일정에 넣기'. 일정에서 시각을 바꿔도 모임의 시간은 안 따라간다 — 남에게 알린 시간은 모임 쪽이 기준이다. 모임 쪽에서 시간을 바꾸면 일정이 따라간다

## 5. 화면

**들어가는 곳**: 사이드바에 `모임`(`/meet`). 홈 타일에도.

**목록 `/meet`**
- 카드 셋: **정할 것**(맞추는 중 · 미정) · **다가오는 모임** · **지난 모임**(접힘, 최근 것부터)
- 줄 하나 = 제목 · 시각(또는 후보 날짜 범위) · 묶음 이름 · 사람 수(숫자만). 지점은 색 점
- **정렬**: 날짜 · 묶음 · 역할 (+ 오름/내림). 묶음 · 역할로 정렬하면 경계에 이름 + 선(플래너와 같은 방식). 필터는 없다
- 새 모임. 묶음 관리는 정렬 옆 작은 단추 → 묶음 이름 · 사람들 · 역할을 고치는 시트

**모임 `/meet/[id]` (나)**
- 위: 제목 · 묶음 · 언제 · 어디서. 수정 · 링크 · 다음 모임 · 지우기
- **사람들**: 이름 줄. 정해진 뒤에는 이름 옆을 눌러 온다 / 못 온다(끝냄 체크처럼 '수정' 없이 바로). 수정 모드에서 사람 넣고 빼기 · **핀 지우기**
- **맞추는 중이면 격자**: 열 = 날짜, 행 = 30분. 겹침은 키위 진하기, 내 되는 칸은 안쪽 점. 옆(폰은 아래)에 추천 시간 줄들. 사람 이름을 누르면 그 사람 것만 강조. 내 칸은 '수정' 뒤에만 칠해진다
- **할 일**: 이 모임에서 나온 것들 + 한 줄 더하기
- **메모**
- 데스크톱은 폭을 다 쓰지 않고 두 열(왼쪽 격자 또는 내용, 오른쪽 사람 · 추천 시간 · 할 일). 폰은 한 열

**공개 페이지 `/m/[열쇠]`** (로그인 없음, `noindex`)
- 처음: 제목 · 지점 · 사람 이름들(미리 넣어 둔 사람은 눌러서 고르고, 없으면 새 이름을 적는다) → **핀번호**(처음이면 정하기, 다시 오면 확인). 이 기기에서는 이름과 핀을 기억해 다시 묻지 않는다
- 핀이 틀리면 "핀번호가 다릅니다. 잊었으면 주최자에게 지워 달라고 하세요" — 5번 틀리면 10분 잠김
- 맞추는 중: 격자. 끌어서 칠하고, 칠한 칸에서 끌면 지운다. 손을 떼면 저장. 다른 사람들 겹침은 같은 격자에 옅게, 내 칸은 진한 테두리
- 정해진 뒤: 정한 날짜 · 시각 · 지점이 크게 + **온다 / 못 온다**. 격자는 읽기만
- 폰: 시간 열 왼쪽 고정, 날짜가 많으면 가로로 넘긴다. **격자 위에서 누른 채 움직이면 칠하기**, 스크롤은 격자 밖에서 — 그래서 격자가 화면을 다 덮지 않게 칸 높이를 줄인다
- 없는 열쇠 · 지운 모임 · 링크를 끈 모임: "없는 링크입니다"
- 밝기 전환 단추는 여기에도

**공통**: 저장은 화면 먼저(낙관적), 실패하면 되돌리고 알림. 모션은 `docs/모션.md`. 지우기는 알림에 '되돌리기'.

## 6. MCP 도구 (2개 — 합쳐서 14개)

| 도구 | 하는 일 |
|---|---|
| `meet_get(id?, circle?)` | id 없으면 목록(묶음으로 좁힐 수 있음) + 묶음들. 있으면 모임 + 사람(참석, 칠했는지) + 추천 시간 + 공개 링크 + 딸린 할 일 |
| `meet_save(id?, …)` | 모임 만들기 · 고치기 · 사람 넣고 빼기 · 참석 · 정하기 · 다시 열기 · 지우기, 묶음 만들기 · 고치기. 만들면 내 되는 시간을 자동으로 채운다 |

에이전트가 남의 칸을 넣거나 핀을 다루는 길은 없다. 할 일은 기존 `todo_save` 에 `meet` 를 받게 한다.

## 7. 엣지

| 경우 | 어떻게 |
|---|---|
| 후보 날짜 · 범위를 줄임 | 밖으로 나간 칸은 계산에서 빠질 뿐 지우지 않는다(다시 넓히면 살아난다) |
| 같은 이름을 다른 사람이 적음 | 핀이 달라서 못 들어온다 → 다른 이름을 적게 된다 |
| 핀을 잊음 | 주최자가 그 사람의 핀을 지운다 → 그 이름으로 다시 들어오며 새 핀. 칠한 것은 그대로 |
| 미리 넣어 둔 사람의 이름을 남이 먼저 차지 | 주최자가 핀을 지우면 된다. 아는 사람끼리라 감수 |
| 두 사람이 동시에 저장 | 줄이 사람마다 따로라 서로 안 덮는다. 저장 결과로 최신 전체를 받는다 |
| 내 이름 | 계정 이름이 따로 없으므로 일정 설정에 `내 이름` 한 칸(처음 모임을 만들 때 묻고 기억). 남은 내 이름으로 못 들어온다 |
| 사람을 뺌 | 그 줄(칠한 것 · 참석)이 지워진다. 알림에 되돌리기 |
| 묶음의 사람을 바꿈 | 이미 만든 모임은 안 바뀐다. 다음 모임부터 |
| 정한 뒤 들어온 남 | 정해진 시간과 온다 / 못 온다만 |
| 후보 날짜가 전부 지남 | '정할 것' 에 남되 추천 시간 없음 |
| 지점을 지움 | `place_id` 가 비고 모임은 그대로 |
| 모임을 지움 | 소프트 삭제 + 알림의 되돌리기. 링크는 바로 죽는다. 딸린 일정 · 할 일은 남긴다 |
| 50명 넘김 | "더는 받을 수 없습니다" |

## 8. 시험

- `lib/meet`: 자동 채우기(이동 · 준비 포함, 반쪽 빈 칸 제외), 겹침, 추천 시간 차례 · 겹치는 묶음 정리 · 지난 시각 제외, 상태 읽기, 정렬
- DB(PGlite): anon 이 테이블을 못 읽음, `ez_meet_public` 이 메모 · 핀 · 내부 값을 안 흘림, 핀 설정 · 확인 · 잠금 · 지운 뒤 다시 설정, `ez_meet_answer` 검사 전부, 정하기 · 다시 열기가 일정과 한 묶음, 남의 모임에 못 닿음
- 화면: 격자 그리기, 칠하기 로직(끌기 범위 → 칸 집합), 목록 정렬 · 경계선, 폰 폭

## 9. 순서 (두 덩어리로 나눠 각각 배포)

**가. 약속 관리** — 남이 안 들어와도 쓸 수 있는 부분

**나. 시간 맞추기** — 공개 페이지

10. 브라우저 확인(데스크톱 · 폰) → 원격 DB 적용 → 배포
