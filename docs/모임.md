# 모임 — 설계서 v1

여럿이 만날 시간을 맞추고, 정해지면 일정으로 넘긴다. 웬투밋(When2meet)의 자리를 대신하되 **내 일정을 이미 아는** 도구라는 점을 쓴다.
기준 문서: 이 문서. 일정 쪽 규칙은 `docs/일정.md`, 공개 링크 방식은 `docs/보고서-서랍.md` 5장 "공유".

## 0. 정해진 것 (2026-10-02)

- 다음 모듈은 모임. 프로젝트 관리(질문지 · 유저플로우 · IA 묶음)는 그다음
- **남은 로그인 없이** 링크로 들어와 이름만 적고 되는 시간을 칠한다
- **내 되는 시간은 일정에서 자동으로** 채운다
- 시간을 정하면 **일정에 약속으로** 들어간다 (`ez_events.origin_kind = 'meet'` — 0006 에 구멍이 이미 있다)
- 1차에서 뺀 것: 장소 투표 · 회의 기록 · 알림 · 캘린더 연동 · 댓글
- 미니멀 1차(설명 문구 · 라벨 · 상태 칩 없음), 포인트 색은 키위 하나, 모든 화면에서 밝기 전환, 한글은 띄어쓰기에서만 줄바꿈

## 1. 웬투밋을 넘어서는 것

| | 웬투밋 | 여기 |
|---|---|---|
| 내 되는 시간 | 매번 손으로 칠함 | 일정(수업 · 근무 · 이동 · 준비)을 빼고 자동으로 칠해짐. 일정이 바뀌면 따라 바뀜 |
| 남에게 보이는 것 | — | 되는 칸만. **일정 제목 · 장소는 절대 안 나간다** |
| 정한 뒤 | 끝. 캘린더에 따로 적음 | 한 번 눌러 일정에 들어감. 이동 · 준비는 일정이 계산 |
| 폰 | 격자가 작고 스크롤과 칠하기가 싸움 | 시간 열 고정 + 날짜 가로 넘기기, 칠하는 동안만 스크롤을 막음 |
| 결과 읽기 | 격자를 눈으로 훑음 | "다 되는 시간 / 가장 많이 되는 시간" 을 길이에 맞춰 뽑아 줌 |

시간 맞추기만으로는 국내 대체재(모두의시간 · 되는시간)와 다르지 않다. 다른 점은 위 첫 줄과 셋째 줄 — **일정과 붙어 있다**는 것 하나다.

## 2. 데이터

### `ez_meets` 모임

| 칸 | | 규칙 |
|---|---|---|
| `id` `owner` `created_at` `updated_at` `deleted_at` | | 다른 `ez_` 테이블과 같다. RLS `owner = auth.uid()` |
| `title` | text | 1~60자 |
| `note` | text? | ≤ 500자. 공개 페이지에 보인다 |
| `place_id` | uuid? → `ez_places` | 내 지점에서 고름. 공개 페이지에는 지점 **이름만** |
| `place_text` | text? | 지점에 없는 곳을 글자로(≤ 60자). `place_id` 와 둘 중 하나 또는 둘 다 없음 |
| `dates` | date[] | 후보 날짜 1~31개, 겹침 없음, 오름차순 |
| `day_from` `day_to` | int | 하루 범위(분). 30분 단위, `0 ≤ from < to ≤ 1440`. 기본은 일정 설정의 하루 범위 |
| `duration_min` | int | 모임 길이. 30~480, 30분 단위. 기본 60 |
| `token` | text | 공개 링크 열쇠, 추측 불가 22자(보고서 공유와 같은 규칙). 만들 때 생김 |
| `decided_date` `decided_start` `decided_end` | date · int · int | 정한 시간. 셋 다 있거나 셋 다 없음 = 아직 열림 |
| `event_id` | uuid? → `ez_events` on delete set null | 정하면서 만든 일정 |

- 칸 하나는 **30분**으로 고정(1차). 15분 · 1시간 단위는 안 넣는다
- 자정을 넘기는 범위는 없다(`day_to ≤ 1440`). 시간대는 한국 시간 하나로 본다 — 남도 한국에 있다고 친다

### `ez_meet_answers` 되는 시간

| 칸 | | 규칙 |
|---|---|---|
| `id` `meet_id` `created_at` `updated_at` | | `meet_id` → `ez_meets` on delete cascade |
| `name` | text | 1~20자, 앞뒤 공백 제거. 한 모임 안에서 대소문자 · 공백 무시하고 겹침 없음 |
| `is_owner` | bool | 주인의 줄. 모임당 최대 1개 |
| `auto` | bool | 주인 줄만: 일정에서 자동으로 채운 상태인지 (3장) |
| `cells` | jsonb | `{"2026-10-05":[540,570,600], …}` — 날짜별 **되는 칸의 시작 분**. 오름차순, 겹침 없음 |

- 날짜를 열쇠로 적으므로 주인이 후보 날짜 · 범위를 바꿔도 번호가 밀리지 않는다. 범위 밖 칸은 그냥 무시된다
- 한 모임에 답은 50개까지
- RLS: 주인만 직접 읽고 지운다. **남은 테이블에 직접 닿지 못하고** 아래 함수로만 드나든다

### DB 함수

| 함수 | 누가 | 하는 일 |
|---|---|---|
| `ez_meet_public(token)` | anon | 공개 페이지가 읽는 것 전부: 제목 · 메모 · 지점 이름 · 날짜 · 범위 · 길이 · 정한 시간 · 답들(이름, 칸, 주인 여부). `owner` · `id` · 일정 내용은 안 준다. 없는 열쇠 · 지운 모임은 빈 결과("없는 링크입니다" — 있었는지 드러내지 않음) |
| `ez_meet_answer(token, name, cells)` | anon | 그 이름의 답을 넣거나 바꾼다. 검사: 모임이 열려 있음 · 이름 규칙 · 칸이 30분 단위이고 후보 날짜 · 범위 안 · 50명 한도. 주인 이름과 같은 이름은 거절. 결과로 전체 답을 다시 준다 |
| `ez_meet_decide(id, base_version?, date, start, end)` | 주인 | 한 번에: 일정 한 건 만들기(제목 · 지점 · 날짜 · 시각, `origin_kind='meet'`, `origin_id=id`) + 모임에 정한 시간 · `event_id` 적기. 범위 · 날짜 검사 |
| `ez_meet_reopen(id)` | 주인 | 정한 것을 무르고 다시 연다. 딸린 일정이 남아 있으면 같이 지운다 |

- 주인의 만들기 · 고치기 · 지우기 · 자기 답 저장은 RLS 아래 테이블에 직접(다른 모듈과 같은 방식). `service_role` 용 `p_as` 는 MCP 가 쓰는 함수에만
- 열쇠는 22자 무작위라 훑어 맞히기는 못 한다. 그래도 anon 이 쓰는 함수이므로 크기를 전부 막는다: 이름 20자 · 답 50개 · 칸 수는 `날짜 31 × 하루 48` 이 상한

## 3. 계산 (`lib/meet/` — 순수 함수, 웹과 MCP 가 같이 쓴다)

**내 되는 시간 (자동)**
- 후보 날짜마다 `lib/schedule` 의 `planRange` → `freeSlots` 로 빈 시간을 구해, **통째로 비는 30분 칸**만 되는 칸으로 친다. 일정뿐 아니라 그 일정에 딸린 준비 · 이동도 바쁜 시간이다(이미 `busyOf` 가 그렇게 한다)
- 종일 일정은 바쁜 것으로 치지 않는다(지금 `busyOf` 와 같다)
- 주인 줄이 `auto = true` 인 동안은 **주인이 모임 화면을 열 때마다 다시 계산해 저장**한다. 서버가 없으므로 "화면을 열 때" 가 갱신 시점이다(플래너의 반복 규칙과 같은 방식)
- 주인이 손으로 한 칸이라도 칠하거나 지우면 `auto = false` — 그 뒤로는 안 건드린다. "일정에 맞추기" 로 되돌릴 수 있다
- 이 모임 자체로 가는 이동시간은 1차에서 안 본다(정한 뒤 일정이 이동 블록을 만들고, 겹치면 일정 화면이 알려 준다)

**겹침**
- 칸마다 되는 사람 수. 격자의 색 진하기는 `되는 수 ÷ 답한 사람 수` 를 키위 4단으로
- 답이 하나도 없으면 전부 빈 격자

**추천 시간**
- 길이 `duration_min` 만큼 이어진 칸 묶음(30분씩 밀어 가며)마다 **끝까지 다 되는 사람 수**를 센다
- 차례: 사람 수 많은 순 → 주인이 되는 것 먼저 → 이른 날짜 · 이른 시각. 겹치는 묶음은 가장 이른 것 하나만 남긴다(10:00, 10:30, 11:00 이 줄줄이 나오지 않게)
- 위에서 5개까지. 0명짜리는 안 보인다
- 지난 날짜 · 지난 시각은 뺀다

## 4. 정하기 → 일정

- 주인이 추천 시간을 누르거나 격자에서 칸을 눌러 시간을 본다 → **'이 시간으로'** 를 한 번 더 눌러야 정해진다(누르면 보기만, 고치기는 한 번 더 — 일정 · 플래너와 같은 규칙)
- 정하면: 일정 한 건이 생기고(제목 = 모임 제목, 지점 = `place_id`, 메모에 `place_text`), 모임은 닫힌다. 공개 페이지에는 정한 날짜 · 시각이 크게 보이고 더는 칠할 수 없다
- 일정 화면에서 그 약속을 고치거나 지워도 된다(내 일정이므로). 지워서 `event_id` 가 비면 모임 화면에 '일정에 다시 넣기' 가 보인다. 일정 쪽에서 시각을 바꿔도 모임의 정한 시간은 안 따라간다 — 남에게 알린 시간은 모임 쪽이 기준이다
- **다시 열기**: 정한 것을 무르고 다시 칠할 수 있게. 딸린 일정은 같이 지운다

## 5. 화면

**들어가는 곳**: 사이드바에 `모임`(`/meet`). 홈 타일에도.

**목록 `/meet`**
- 카드 둘: 맞추는 중 · 정해짐(지난 것은 접힘). 줄 하나 = 제목 · 날짜 범위 또는 정한 시각 · 답한 사람 수(숫자만)
- 새 모임: 제목 → 날짜(작은 달력에서 누르거나 끌어 여러 날) → 하루 범위 · 길이 · 지점 · 메모. 제목과 날짜만 있으면 만들어진다

**모임 `/meet/[id]` (주인)**
- 위: 제목 · 링크 복사 · 수정 · 지우기
- 가운데: **격자 하나**. 열 = 날짜, 행 = 30분. 겹침은 키위 진하기, 내 되는 칸은 안쪽 점 하나
- 옆(폰은 아래): 추천 시간 줄들, 답한 사람 이름들(누르면 그 사람 것만 격자에 남김 — 필터가 아니라 강조)
- 내 칸 고치기는 '수정' 을 누른 뒤에만 칠해진다. 그 전에는 눌러도 그 칸의 되는 사람 이름만 보인다
- 데스크톱은 격자 폭을 다 쓰지 않는다(날짜 열 최대 폭을 두고 옆에 패널 — 일정과 같은 원칙)

**공개 페이지 `/m/[열쇠]`** (로그인 없음, `noindex`)
- 처음: 제목 · 메모 · 지점 · 이름 칸 하나. 이름을 적으면 격자가 열린다. 같은 이름으로 다시 들어오면 **그 답을 이어서 고친다**(웬투밋 방식 — 비밀번호 없음). 이 기기에서는 이름을 기억해 다시 묻지 않는다
- 격자: 끌어서 칠하고, 칠한 칸에서 끌면 지운다. 손을 떼면 저장(따로 저장 단추 없음). 다른 사람들 겹침은 같은 격자에 옅게 깔려 있고, 내 칸은 진한 테두리
- 폰: 시간 열은 왼쪽 고정, 날짜가 많으면 가로로 넘긴다. **격자 위에서 누른 채 움직이면 칠하기**, 스크롤은 격자 밖 또는 두 손가락 — 대신 격자 높이가 화면을 넘지 않게 칸 높이를 줄인다(범위가 길면 격자 안에서만 세로 스크롤 띠)
- 정해진 모임: 정한 날짜 · 시각 · 지점만 크게. 격자는 읽기만
- 없는 열쇠 · 지운 모임: "없는 링크입니다"
- 밝기 전환 단추는 여기에도 있다

**공통**: 저장은 화면 먼저(낙관적), 실패하면 되돌리고 알림. 모션은 `docs/모션.md`. 지우기는 알림에 '되돌리기'.

## 6. MCP 도구 (2개 — 합쳐서 14개)

| 도구 | 하는 일 |
|---|---|
| `meet_get(id?)` | id 없으면 목록. 있으면 모임 + 답한 사람 + 추천 시간(3장 그대로) + 공개 링크 |
| `meet_save(id?, …, decide?, reopen?, delete?)` | 만들기 · 고치기 · 정하기 · 다시 열기 · 지우기. 만들면 내 되는 시간을 자동으로 채운다 |

에이전트가 남의 답을 넣거나 고치는 길은 없다(남의 답은 공개 페이지로만).

## 7. 엣지

| 경우 | 어떻게 |
|---|---|
| 주인이 날짜 · 범위를 줄임 | 밖으로 나간 칸은 계산에서 빠질 뿐 지우지 않는다(다시 넓히면 살아난다) |
| 같은 이름 두 사람 | 같은 사람으로 본다 — 뒤에 온 사람이 앞사람 답을 보고 고치게 된다. 이름 칸 밑에 그 이름의 답이 이미 있으면 칠해진 채로 열리므로 알아챌 수 있다 |
| 두 사람이 동시에 저장 | 답은 사람마다 따로라 서로 안 덮는다. 저장 결과로 최신 전체를 받아 격자를 고친다 |
| 한 사람이 두 기기에서 | 나중 저장이 이긴다 |
| 답 50개 넘김 | "더는 받을 수 없습니다" |
| 정한 뒤 들어온 남 | 정한 시간만 보인다. 저장 함수도 거절한다 |
| 후보 날짜가 전부 지남 | 목록에서 '지난 것' 으로 접힘. 추천 시간 없음 |
| 지점을 지움 | `place_id` 가 비고 모임은 그대로 |
| 주인 이름 | 계정 이름이 따로 없으므로 일정 설정에 `내 이름` 한 칸을 둔다(처음 모임을 만들 때 묻고 기억) |
| 남이 주인 이름으로 답함 | 거절("이미 있는 이름입니다") |
| 모임을 지움 | 휴지통 없이 소프트 삭제 + 알림의 되돌리기. 링크는 바로 죽는다. 딸린 일정은 남긴다 |

## 8. 시험

- `lib/meet`: 자동 채우기(이동 · 준비 포함, 반쪽 빈 칸 제외), 겹침, 추천 시간 차례 · 겹치는 묶음 정리 · 지난 시각 제외
- DB(PGlite): anon 이 테이블을 못 읽음, `ez_meet_public` 이 내부 값을 안 흘림, `ez_meet_answer` 검사 전부, 정하기 · 다시 열기가 일정과 한 묶음으로 됨, 남의 모임에 못 닿음
- 화면: 격자 그리기, 칠하기 로직(끌기 범위 → 칸 집합), 폰 폭

## 9. 순서

1. `lib/meet` 순수 로직 + 시험
2. DB `0011_ez_meets.sql` + 시험
3. 데이터 계층(실제 · 데모) + MCP 도구 2개
4. 주인 화면(목록 · 만들기 · 모임)
5. 공개 페이지 `/m/[열쇠]`
6. 정하기 → 일정, 다시 열기
7. 실제 브라우저 확인(데스크톱 · 폰) → 원격 DB 적용 → 배포

## 10. 정해야 할 것 (추천을 기본값으로 진행)

| | 추천 | 다른 길 |
|---|---|---|
