# 공통 화면 규칙 (2026-10-04)

모듈마다 따로 정하지 않고 사이트 전체에 적용하는 두 가지. 모듈 설계서보다 우선한다.

## 1. 내용은 가운데에

> "섹션들을 전체적으로 중앙으로 보낼 필요가 있음. 너무 다 왼쪽 정렬인 게 불편해, 사이트 전반적으로."

- 모듈의 **내용 기둥**(목록 · 카드 · 폼 · 표)은 최대 폭을 두고 **작업면 가운데**에 둔다(`margin: 0 auto`). 사이드바를 뺀 나머지 폭에서 가운데
- **조작 줄**(정렬 · 역할 칩 · 검색 · 단추 줄)은 그 내용 기둥과 **같은 폭 · 같은 왼쪽 선**에 맞춘다 — 조작은 왼쪽 정렬이지만 기둥 자체가 가운데라, 넓은 화면에서 왼쪽 끝에 붙지 않는다. 위쪽 바(홈 · 빵부스러기 · 밝기 전환)는 지금처럼 작업면 폭을 다 쓴다
- 기둥 최대 폭: 플래너 두 열 1,200 · 한 열 760 / 작업대 목록 760(가져올 것이 옆에 있으면 카드 760 + 가져올 것 320 = 1,104) · 집중 960 · 기록 960 / 모임 목록 1,040 · 모임 하나 1,040 / 보고서 1,032 + 레일(이미 가운데) / 서랍 탐색기 1,200 / 일정 설정 720 / 관리(회원) 960 / 홈 1,100. 주간 시간표(`/schedule`)는 폭을 다 쓰는 격자라 그대로
- 폰(작업면 760 미만)은 지금처럼 가득 — 바뀌지 않는다
- 데스크톱 두 열이던 것은 그대로 두 열, 기둥만 가운데
- 만든 방식(2026-10-04): 모임 목록이 한 열일 때는 플래너 한 열처럼 760. 서랍 탐색기 · 홈은 빈 곳 누르기 · 우클릭이 작업면 전체에 남도록 `max-width` 대신 좌우 여백 `max(원래 여백, (100% − 기둥) / 2)` 로 가운데. 스크롤 상자(플래너 · 모임 · 작업대 목록, 일정 설정, 관리)는 스크롤바 자리를 양쪽에 둬(`scrollbar-gutter: stable both-edges`) 좌우 여백을 맞춘다. 플래너 · 모임 목록의 조작 줄(`.pl-ctl`)은 목록과 같은 여백 · 같은 스크롤바 자리를 두고 넓은 화면의 보기 패널이 열리면 그 폭만큼 오른쪽을 비운다

## 2. 우클릭 메뉴는 어디서나

> "우클릭 메뉴도 다 있으면 좋겠고."

- 줄 · 카드 · 블록처럼 **누를 수 있는 항목**에는 **우클릭(터치는 길게 누르기) 메뉴**가 있다. 탐색기의 메뉴(`app/_ui/Menu.tsx`, 길게 누르기 포함)와 같은 모양 · 같은 동작
- 메뉴 항목은 **그 화면에 이미 있는 동작만** 모은다(새 기능을 메뉴에만 넣지 않는다). 첫 항목은 "열기/보기", 지우기는 맨 아래, 그 위에 구분선. 아이콘은 `Icon.tsx` 에 있는 것만
- 어디에 무엇을
  - 플래너 할 일 줄: 보기 · 끝냄(또는 되살리기) · 작업대(또는 작업대에서 내리기) · 수정 · 시간 정하기(또는 다시 정하기 · 시간 없음으로) · 일정으로 보내기 · 반복으로 만들기(반복에서 온 회차에는 없음) · 지우기
  - 플래너 반복 카드의 규칙 줄: 보기 · 수정 · 멈춤(또는 다시 시작) · 지우기
  - 작업대 목록 카드: 집중 화면 · 끝냄 · 내리기
  - 작업대 목록의 가져올 만한 것 줄: 작업대에 올리기
  - 집중 화면의 단계 줄: 체크 · 들이기 · 내기(될 때만) · 떼어내기 · 지우기(단계)
  - 기록 표의 할 일 줄: 보기 · 집중 화면(작업대에 올라가 있을 때)
  - 모임 목록 줄: 열기 · 수정 · 다음 모임 · 링크 복사(켜져 있을 때) · 지우기
  - 모임 화면의 사람 줄: 온다 · 못 온다 · 비우기(정해진 뒤) · 핀 지우기 · 빼기
  - 일정 블록(주간 · 하루): 보기 · 수정 · 이번만 바꾸기(반복이면) · 지우기(반복이면 이번만 / 이후 모두 — 보기 패널의 없애기 범위와 같다)
  - 보고서 블록(고치기 모드): 댓글 · 위로 · 아래로 · 지우기. 읽기 모드: 댓글 · Markdown 으로 복사(그 블록만)
  - 보고서 서랍 탐색기: 지금 그대로
  - 관리(회원) 표 줄: 이름 고치기 · 비밀번호 다시 정하기 · 켬/끔 · 지우기
- 메뉴를 연 항목은 메뉴가 떠 있는 동안 선택 표시(탐색기와 같다). Esc · 바깥 누르기 · 스크롤로 닫힘. 키보드: 메뉴 키(`ContextMenu` · Shift+F10)도 연다
- 폰 길게 누르기: 500ms, 그 사이 손가락이 10px 넘게 움직이면 취소(탐색기 규칙). 길게 누른 뒤 손을 떼도 열기(탭)가 같이 일어나지 않는다
- 만든 방식(2026-10-04): 열기 · 닫기 · 길게 누르기 · 키보드는 훅 하나(`app/_ui/useContextMenu.tsx`), 화면별 · 상태별 항목 목록은 순수 함수(`app/_logic/menus.ts`, 시험 있음). 탐색기는 고르기와 얽혀 자기 것 그대로(길게 누르기 520ms). 키보드로 연 메뉴는 그 항목 왼쪽 아래에 뜨고, 닫히면 초점이 그 항목으로 돌아온다. 항목이 하나도 없으면(저장 전 임시 줄 · 만드는 중인 일정 칸 · 고치는 중인 블록) 브라우저 기본 메뉴
  - 우클릭이 브라우저 기본 메뉴로 가는 때: 커서가 있던 칸(입력 · 고치는 글자) 안, 그 항목 안에 글자를 골라 둔 채. 터치는 칸 안 길게 누르기를 글자 고르기에 둔다
  - 플래너: 시간 항목 · 일정으로 보내기는 보기 패널의 단추와 같은 조건(지난 마감이면 시간 항목 없음, 반복 일정에 이어진 것은 시간을 여기서 안 바꾼다). 작업대에 올라가 있으면 "작업대에" 대신 "작업대에서 내리기". 끝낸 할 일은 보기 · 되살리기 · 수정 · 지우기
  - 집중 화면 단계의 지우기는 되돌리기 알림이 붙는다(같은 자리에 다시)
  - 모임 목록: 수정은 그 모임 화면으로 가서 수정 칸을 연 채로(`?edit=1`), 다음 모임은 만들고 그리로 간다, 지우기는 목록에 남고 되돌리기 알림
  - 모임 사람 줄: 참석은 정해진 뒤에만 · 지금 고른 값은 빼고, 비우기는 고른 게 있을 때. 핀 지우기 · 빼기는 화면에서는 수정 중에만 보이지만 메뉴에서는 언제나(나는 못 뺀다)
  - 일정: 바깥에서 온 일정은 보기만. "이번만 바꾸기" 는 수정 칸을 열고 저장 범위를 이번만으로 둔다(반복 규칙을 바꾸면 이후 모두만 남는 것은 그대로)
  - 보고서 고치기 모드: 메뉴를 연 블록이 고른 것에 없으면 그것만 고르고, 위로 · 아래로 · 지우기는 고른 것 전체에(도구 줄과 같다). 옮길 수 없는 쪽은 빠진다. 댓글은 고치기 모드를 끄고 그 블록의 댓글 줄을 연다. 손잡이 길게 누르기는 끌기 몫이라 메뉴를 재지 않는다
  - 보고서 읽기 모드의 Markdown 복사는 `lib/markdown` 의 `blockToMarkdown` — 보고서 전체로 옮길 때와 같은 글, 인용 번호도 그대로
  - 관리: 이름 고치기 · 비밀번호 다시 정하기는 시트를 열고 그 칸으로, 지우기는 시트의 확인 단추(한 번 더 눌러야 지운다)

## 3. 화면이 커지면 같이 커진다 (2026-10-04)

> "FHD · QHD 는 화면 비율이 똑같으니까 UI 들의 비율도 똑같으면 좋겠어. QHD 기준으로 지금 좀 작은 것 같아."

- **기준 폭 1,920**. 창 폭이 그보다 넓으면 화면 전체를 `창 폭 ÷ 1,920` 배로 키운다 — QHD(2,560)에서 1.333배, 4K(3,840)에서 2배(상한 2). 그러면 QHD 에서 보이는 배치 · 글자 크기 **비율이 FHD 와 똑같다**. 1,920 이하는 그대로(1배) — 좁은 폭은 지금의 반응형이 맡는다
- 방법: 루트(`html`)에 CSS `zoom`. 값은 작은 스크립트가 창 크기에 맞춰 넣는다(첫 그림 전에 한 번 — 깜빡임 없게 `<head>` 인라인, 그리고 `resize` 때). CSS 변수 `--zoom` 에도 같은 값을 둔다
- **조심할 곳** — `zoom` 아래에서는 화면 좌표(포인터 `clientX/Y` · `getBoundingClientRect`)와 CSS 길이(px)가 `zoom` 배만큼 어긋난다. 좌표를 길이로 되돌려 쓰는 코드는 전부 `zoom` 으로 나눠야 한다. 한 곳에 도우미(`app/_logic/zoom.ts`: `zoom()` · `toCss(px)` · `rectCss(el)`)를 두고 고친다:
  - 일정 격자 끌기 · 놓기(포인터 Y → 분), 모임 격자 칠하기, 보고서 블록 끌어 옮기기 · 놓일 선, 댓글 옆 패널 자리, 목록 재배치 모션(FLIP), 폰 좌우 밀기, 우클릭 메뉴 · 팝업 · 인용 미리보기 위치, 가장자리 자동 스크롤, `100vh`/`dvh` 로 잡은 높이(사이드바 · 한 화면 앱 높이 — `zoom` 아래에서 넘치지 않게 `calc(100dvh / var(--zoom))`)
- 공개 페이지(`/s/…` · `/m/…`) · 로그인도 같은 규칙
- 폰 · 태블릿은 폭이 1,920 을 안 넘으니 영향 없다
- **브라우저 자체 확대(Ctrl +/−)와는 겹치지 않는다** (잰 결과로 고침). 브라우저 확대는 창 폭(CSS px)을 바꾸는데 배율이 그 창 폭에서 나오므로, 창 폭이 1,920 을 넘는 동안에는 둘이 서로 지운다 — QHD 에서 Ctrl + 125% 는 그대로(1.25 × 1.067 = 1.333), 133% 를 넘어야 커진다. FHD 에서 Ctrl − 90% · 75% 도 줄지 않는다(창 폭이 2,133 · 2,560 이 돼 다시 키운다), 50% 아래부터 준다. 창 폭만으로는 "큰 화면" 과 "브라우저를 줄인 화면" 을 가를 수 없다
- 만든 방식(2026-10-04)
  - 스크립트 · 식 · 도우미는 `app/_logic/zoom.ts` 한 곳: `zoomFor(폭)` · `ZOOM_SCRIPT`(`app/layout.tsx` 의 `<head>` 에 그대로 — 1 이면 아무것도 넣지 않아 1,920 이하는 전과 같은 문서) · `zoom()` · `toCss` · `toScreen` · `rectCss` · `viewCss`. 값마다 어느 좌표계인지 크롬에서 잰 표가 그 파일 머리에 있다
  - **화면 px**(zoom 이 곱해진 값): `getBoundingClientRect` · 포인터/터치 `clientX/Y` · `elementFromPoint` · `innerWidth/Height` · 문서(창) 스크롤 · `vh`/`vw` · `@media`. **CSS px**: `style` 에 쓰는 길이 · `offset*` · `clientWidth` · 안쪽 상자의 `scrollTop` · `@container`. 화면 px 를 길이로 쓰거나 CSS px 값과 섞을 때만 `toCss` 로 나눈다 — 화면 px 끼리 견주는 것(포인터가 rect 안인가 · `elementFromPoint` · 비율)은 그대로
  - 반응형 분기는 거의 `@container` 라 확대 전 폭(1,920)을 본다 — 그대로 맞는다. JS 의 폰 · 넓은 화면 판정은 `viewCss().w`(확대 전 폭). `@media (max-width: 760px)` 하나는 창 폭을 보지만 1,920 밑의 분기라 영향 없다. **1,920 보다 큰 값으로 `@media` · `matchMedia` 분기를 만들지 않는다**(확대된 화면에서는 창 폭이 그대로 보인다)
  - `vh` · `vw` · `dvh` 는 zoom 을 모른다(100vh 가 화면의 1.333배로 넘친다). `globals.css` 의 `:root` 에 `--vh` · `--vw` · `--dvh`(`calc(1vh / var(--zoom))`)를 두고 `calc(100 * var(--dvh))` 처럼 쓴다. **새 CSS 에 `vh` · `vw` 를 바로 쓰지 않는다.** `%` · `inset: 0` 은 그대로 맞는다
  - 메뉴(`Menu`) · 추가 모듈 창은 **화면 좌표를 받아** 안에서 길이로 바꾼다 — 부르는 쪽은 `clientX/Y` · rect 를 그대로 넘긴다
  - 스크롤바는 커지지 않는다(15px 그대로). 스크롤바 자리를 둔 상자는 QHD 에서 내용이 3.75~7.5px(0.2~0.4%) 넓다 — 둔다
  - 상한 2 를 넘는 창(폭 3,840 초과)은 2배로만 키우고 남는 폭은 지금의 반응형대로 넓어진다
- 시험: `zoom` 계산(순수 함수: 1,920 → 1 · 2,560 → 1.333 · 3,840 → 2 · 1,440 → 1), 좌표 변환. 화면은 headless 로 **2,560 × 1,440 과 1,920 × 1,080 스크린샷을 같은 크기로 줄여 겹쳐 봤을 때 배치가 같은지**, 그리고 2,560 에서 끌기 · 메뉴 · 패널이 손가락(포인터) 자리에 맞는지
