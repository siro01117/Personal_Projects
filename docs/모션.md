# 모션

화면이 바뀔 때 무엇이 어디서 왔는지 보이게 한다. 조작을 기다리게 하지 않는다 — 이 문서의 원칙이 어느 전환보다 우선이고, 한 전환이 조작을 느리게 하면 그 전환을 뺀다.

## 원칙

1. **빠르고 조용하게.** 140~240ms, 큰 면 이동만 최대 280ms. 감속 곡선 하나(`--ease-out`). 지연(delay) 없음 — 홈 타일의 순차 등장만 예외(전체 200ms 안)
2. **transform · opacity 만 움직인다.** 높이·너비·top/left 는 움직이지 않는다. 접기/펴기만 `grid-template-rows 0fr↔1fr`. `will-change` 는 움직이는 동안만
3. **조작을 막지 않는다.** 움직이는 중에도 누르고 밀 수 있다. 새 조작이 오면 진행 중인 것을 그 자리에서 끊고 이어 간다. 데이터(낙관적 갱신)는 먼저 바꾸고, 애니메이션은 그 뒤를 눈으로만 따라간다 — 끝날 때까지 미루는 상태 변경이 없다
4. **`prefers-reduced-motion: reduce` 면 전부 끈다.** CSS 는 전역 규칙, JS 로 움직이는 것은 `reducedMotion()` 으로 끈다
5. **장식 없음.** 탄성·큰 스케일·색 번쩍임 없음. 스케일은 0.97~1 사이
6. **CSS 먼저.** JS 가 필요한 곳(밀기 · 목록 재배치 · 나가는 것)만 작은 도구로. 라이브러리 없음

## 토큰 (`app/globals.css` `:root`)

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | 전부 |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | 나가는 것 |
| `--m-fast` | `.14s` | 눌림 · 나가는 것 · 테두리 |
| `--m-base` | `.18s` | 패널 내용 · 팝 · 줄 등장 · 재배치 |
| `--m-slow` | `.24s` | 시트 · 하루/주 넘김 |
| `--t` | `var(--m-fast) var(--ease-out)` | 예전부터 쓰던 transition 축약. **animation 축약에는 쓰지 않는다**(둘째 시간이 지연으로 읽힌다) |

JS 쪽 같은 값은 `app/_ui/motion/motion.ts` 의 `MS` · `EASE`.

## 도구 (`app/_ui/motion/`)

- `motion.ts` — `reducedMotion()`, `MS`, `EASE`, `slideIn(요소들, 방향)`(짧게 미끄러져 들어옴), `ghostOut(요소)`(지워질 요소의 복제를 제자리에서 흐리게 내보냄)
- `usePager.ts` — 좌우 밀기. 손가락을 따라 트랙을 옮기고, 놓으면 `onStep(±1)` 을 **바로** 부른다. 화면은 `shift(방향)` 으로 한 폭 옆에서 0 으로 미끄러진다(상태는 이미 바뀐 뒤). 도중에 다시 잡으면 지금 위치에서 이어 간다. 판정은 `app/_logic/swipe.ts`(순수 함수 + 시험)
- `useFlip.ts` — 목록 재배치(FLIP). 커밋마다 줄의 자리를 재서 옮겨진 줄은 옛 자리에서 미끄러지고, 새 줄은 나타나고, 사라진 줄은 복제가 제자리에서 흐려진다. Web Animations 라 줄은 계속 눌린다
- `Presence.tsx` — 조건부로 그리던 것(시트 · 스크림 · 작은 창 · 떠 있는 패널 · 알림)이 사라질 때 `data-leaving` 을 달고 잠깐 더 그린다. 그동안 `inert` + `pointer-events:none` 이라 뒤의 화면이 바로 눌린다

## 밀기 판정 (`app/_logic/swipe.ts`)

- 방향: 8px 움직이기 전에는 정하지 않는다. 가로가 세로의 1.2배보다 크면 가로(세로 스크롤 잠금), 아니면 세로(밀기 포기). 영역은 `touch-action: pan-y`
- 넘김: 놓을 때 속도가 0.35px/ms 이상이면 그 방향으로(끌린 쪽과 반대면 취소), 아니면 끌린 거리가 폭의 25% 이상일 때
- 길이: 남은 거리에 비례해 140~240ms

## 안 한 것

- 페이지 사이 전환(홈 ↔ 모듈, 모듈 ↔ 모듈): `layout.tsx` · `next.config.ts` 를 고쳐야 한다. 방법 — `next.config.ts` 에 `experimental.viewTransition: true`, 링크 이동을 React `<ViewTransition>` 으로 감싸거나 `app/template.tsx` 에 들어오는 애니메이션을 둔다. 지금은 각 화면의 `.view` 가 들어올 때 페이드 + 6px 만 한다
- 메뉴 닫힘 애니메이션: 닫힘은 다음 조작의 시작이라 즉시
- 블록을 끌어 놓은 뒤 자리로 미끄러지는 것: 끄는 동안 이미 15분 칸에 붙어 움직인다. 놓을 때는 그림자 · 투명도만 가라앉는다

## 페이지 전환 (2026-10-02)

과하지 않게 — 움직이는 것은 사이드바의 선택 표시뿐이고, 내용은 흐림 → 또렷만.

- 모듈(보고서 서랍 · 일정 · 플래너 · 휴지통)은 틀 하나(`app/(work)/layout.tsx`)를 같이 쓴다. **사이드바는 모듈을 오가도 다시 그리지 않는다.** 선택 표시(`.nav.slide .ind`)만 메뉴 사이를 미끄러진다
- 오른쪽 내용(`.main.page-in`)은 모듈이 바뀔 때만 다시 붙어 `--m-fast` 로 나타난다. 이동 없음. 모듈 안에서 폴더·주·날을 오갈 때는 그대로(그쪽 전환이 따로 있다)
- 홈 ↔ 모듈은 지금대로: 틀이 한 번 `.view` 로 들어오고, 홈은 타일이 순차로 나타난다
- View Transitions 는 쓰지 않는다(전환 중 누르기를 막는다)
