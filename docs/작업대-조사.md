# 작업대 조사 (2026-10-04)

기준 설계: `docs/플래너.md` 7-13 · 7-15 · 7-16. 코드는 고치지 않았다(읽기만).

표기: **[확인]** 직접 열어 본 것(설계서 · 코드 · 공식 페이지) / **[2차]** 검색 요약이나 제3자 글만 본 것 / **[추측]** 내 판단 / **[확인 필요]** 써 보거나 코드로 더 봐야 하는 것.

## 요약

1. 작업대의 뼈대(단계 · 메모 · 끝냄 · 내리기 · 여러 개)는 벤치마크 도구들이 공통으로 가진 것(한 가지만 보기 · 하위 단계 · 템플릿)과 맞고, 타이머 · 음악 · 게임화를 뺀 것도 미니멀 규칙에 맞다.
2. **가장 큰 구멍은 반복 할 일**이다. 새 회차가 생기면 안 끝낸 지난 회차를 지우는데(`0008_ez_roles.sql:259`), 그 회차가 작업대에 올라 단계 · 메모가 쌓여 있어도 같이 사라진다. [확인]
3. 반복 단계 템플릿은 이미 있다. 규칙의 `checklist` · `note` 가 새 회차로 복사된다(`0008:262-267`). 새 기능이 아니라 "작업대에서 고친 것이 규칙에 가나" 만 정하면 된다. [확인]
4. 막히는 곳은 **착수(열기까지의 탭 수)** 와 **재개(어디까지 했더라)** 다. 재개는 "지금 단계"가 풀어 주는데 목록 카드에는 안 보인다.
5. "앉은 지 n분"은 끊김(수업 · 점심 · 다음 날)에 틀린 숫자를 낸다. 날짜가 바뀌면 해제하는 정도가 싸다.
6. 단계 시간 · 타이머 · 알림 · 음악 · 사이트 차단 · 앱 안 AI 쪼개기 버튼은 안 만든다. 쪼개기는 로컬 Claude 가 MCP 로 한다. 단 "빈 단계를 채우기 · 뒤에 추가만" 규칙이 필요하다.
7. "뭘 했는지" 기록은 따로 안 만든다. 끝낸 할 일이 단계 · 메모를 그대로 들고 남는 것이 기록이다(열람 경로만 확인 필요).
8. 5분짜리(메일 답장)와 바깥 절차(서류)는 작업대에 올릴 이유가 약하다. 작업대는 복습 · 과제 · 준비처럼 **쪼갤 가치가 있는 일**용이다.
9. 더할 것 1순위 셋: 반복 회차가 작업대 진행을 지우지 않게 / 목록 카드에 지금 단계 글자 / 앉은 지를 오늘만.
10. 사용자에게 물을 것 8개는 7장.

## 3. 할 일 종류별 차이

| 종류 | 예 | 작업대 가치 | 필요한 것 | 주의 |
|---|---|---|---|---|
| 반복 복습 | 상법 정리 | 높다. 같은 단계를 매주 | 규칙 단계 템플릿 · 메모 템플릿(범위 · 자료 위치) · 규칙이 작업대에 자동 올림 | 밀린 회차 지움이 진행을 지운다 |
| 산출물 과제 | 운영체제 과제 3, 팀플 발표 자료, APPTIVE 회고 정리 | 가장 높다. 쪼개기가 일의 절반 | 에이전트 초안 단계 · 메모에 요구사항 · 산출물 링크 · 여러 날 이어 하기 | 팀 의존(남의 파트 대기)은 단계가 아니라 내리기 + 메모. 단계가 20개를 넘으면 떼어내기 |
| 5분짜리 | 교수님 메일 답장 | 낮다. 올리고 앉는 비용이 일보다 크다 | 플래너 줄에서 바로 끝냄. 초안은 Claude 에게 | 단계 0개인 할 일도 끝낼 수 있어야 한다 |
| 사람 상대 | 학원 학생 상담, 문자 보내기 | 중간. 상담 전 확인 목록이 단계 구실 | 상담 전 체크 목록 템플릿. 시간은 일정에 | 학생 이름 · 상담 내용을 메모에 적는 것은 개인정보. 저장 정책 [확인 필요] |
| 바깥 절차 | 장학금 서류, 자취방 계약서 확인 | 낮다. 며칠에 걸친 대기가 본질이라 "집중"이 아니다 | 플래너 체크 항목 + 마감으로 충분. 계약서 "읽고 표시할 조항"만 작업대 | 마지막 "접수 확인" 단계가 며칠 뒤. 작업대에 오래 올려 두면 썩는다 |

### 4-2. 연구 근거 (설계 판단에 쓴 것)

| 내용 | 우리 설계와의 관계 | 출처 |
|---|---|---|
| 언제 어디서를 미리 정하는 if-then 계획이 목표 달성에 중간~큰 효과(94건 메타분석 d 약 0.65, 시작 단계에도 효과). 숫자는 검색 요약 | "수업 끝나면 상법 정리"가 이 모양이다. 작업대 자동 올림이 한 칸 더 간다 | [18] [2차] |
| 미완료 목표의 방해 사고는 끝내지 않아도 구체 계획을 세우면 줄어든다(Masicampo · Baumeister 2011) | 단계만 적고 **내리기**도 가치가 있다. 내리기를 실패처럼 보이게 하지 않는다 | [19] [2차] |
| 미완료 일에서 다른 일로 옮기면 주의 일부가 앞의 일에 남는다(attention residue, Leroy). 재개 계획이 줄여 주는지는 검색에서 못 확인 | 전환 전 "다음에 할 것" 한 줄이 가치 있을 수 있다. 전환 마찰은 만들지 않는다 | [20] [2차], 재개 계획은 [확인 필요] |
| 바디더블링: 12명 VR 실험은 과제를 더 빨리 끝냈다. Flown 사용자 117명 조사는 재참여가 빨랐다고 하나 회사 관련 자료일 수 있다 | 사람 없이는 못 한다. 만들지 않는다 | [10] [2차] |

| 단계가 50개를 넘으면 | 한도는 그대로 둔다(과제도 10~20개가 현실적 [추측]). 끝낸 단계가 많으면 접어서 "끝낸 n개" 한 줄, 20개쯤부터는 덩어리를 떼어내 새 할 일로. 한도 오류 문구에 떼어내기를 안내 | 접기 없음 |
| 단계마다 걸릴 시간 | 적지 않는다. 입력 부담 + 압박. 할 일 전체 `est_min` 만. 글자 안에 "(15분)"을 적는 것은 막지 않는다 | 7-13 에서 뺌, 유지 |
| 중간에 급한 일이 끼어든다 | 5분이면 플래너에서 바로 끝냄 / 떠오른 일은 새 할 일 한 줄 / 길면 ‹ › 로 다른 작업대. 전환 때 묻지 않는다. 복귀는 지금 단계가 돕는다 | 있음 |
| 하루가 끝났는데 안 끝남 | 내리지 않으면 작업대에 그대로(의도적으로 올린 것이라 유지가 맞다). 자동으로 넘기지도 지우지도 않는다 | 있음 |

## 6. 추천

### 6-1. 더할 것 (우선순위 순)

1. **반복 회차가 작업대 진행을 지우지 않게.** 데이터 손실이고 "데이터 무결성은 DB" 규칙에 걸린다. 한 곳(roll 함수)에서 막는다.
2. **목록 카드에 지금 단계 글자.** 재개가 목록에서 끝난다. 메모 첫 줄보다 먼저 보여 준다(단계가 없을 때만 메모 첫 줄). 새 라벨이 아니라 있는 줄의 내용만 바꾼다.
3. **"앉은 지"를 오늘만.** 날짜가 바뀌면 해제. 틀린 숫자를 안 내는 가장 싼 방법.
4. **메모 안 링크 열기.** 평소엔 읽기 상태(링크가 눌림), 다른 곳을 누르면 고치기. "누르면 보기 · 고치기는 한 단계 더" 규칙과 맞다. URL 은 http/https 만(공통 규칙).
5. **규칙이 만든 할 일을 작업대에 자동으로 올리는 선택(규칙의 한 칸).** "수업 끝나면 → 단계가 든 작업대가 이미 올라 있음". 착수 탭을 줄인다. 규칙은 한 건만 만들기 때문에 쌓이지 않는다.
6. **열자마자 커서를 지금 단계에(없으면 첫 빈 줄).** 이미 그렇다면 확인만. 착수 저항을 키보드 한 번으로.
7. **끝낸 단계 접기(많을 때만).** 지금 단계 주변만 보이게. 8개 이상일 때처럼 임계값은 써 보고 정한다.
8. **MCP: 단계 추가 전용 · 체크 상태 보존 · 규칙 체크 항목 수정 · `todo_list` 에 지금 단계.** 에이전트가 사용자 계획 위에 덮어쓰지 못하게. 에이전트 지침에 쪼개기 규칙(위 5장)을 적는다.
9. **단계 0개일 때 끝냄을 기본(키위)으로.** 작은 일도 작업대에서 닫을 수 있게(확인 후).
10. **끝낸 할 일에서 단계 · 메모 읽기 경로 확인.** 기록이 읽히지 않으면 기록이 아니다. 필요하면 보기에 이미 있는 칸을 보여 주기만.

### 6-2. 바꿀 것

- 7-13 "뺀 것: 작업 기록" 문구를 "**시간 기록은 안 한다. 끝낸 할 일이 기록**"으로 고쳐 쓴다(설계서 정리).
- 목록 카드의 "앉은 지 n분"을 없애고 앉은 카드의 키위 막대만 남긴다. 흐르는 숫자가 목록에서 눈을 끈다. [추측]
- 진행 막대와 "2/5"가 한 화면에 같이 있다(7-16). 중복 정보 금지 규칙에 걸린다. 사용자가 막대를 원했는지 확인 후 하나만.
- 단계 한도(50) 오류 문구를 "단계는 50개까지. 한 덩어리를 떼어내 새 할 일로 만들 수 있다" 정도의 짧은 안내로.
- 7-1 "자동으로 다음 날로 넘기지 않는다"는 그대로, 작업대는 **의도로 올린 것이라 유지**한다고 7-13 에 한 줄 적는다.

### 6-3. 뺄 것

- 위 "바꿀 것"의 목록 카드 앉은 지 분, 진행 막대 또는 n/m 중 하나. 둘 다 근거가 약해 사용자 확인 후.
- 이미 뺄 것은 없다. 7-13 → 7-16 에서 단계 시간 · 타이머 · 포모도로를 이미 뺐다.

### 6-4. 아직 안 정한 것 — 한결에게 물어본다 (2026-10-04: "미리 못박지 마")

| 후보 | 조사 쪽 의견(결정 아님) |
|---|---|

| 작업 시간 기록 · 통계 | 타이머 없이는 벽시계라 부정확. 틀린 숫자가 추정을 해친다 |

| 작업대 ↔ 보고서 연결 필드 | 질문 1 의 답에 따라. 지금은 Claude 에게 시켜 만드는 보고서로 충분 |

## 7. 사용자에게 물을 것

1. 상법 정리의 결과물은 어디에 남기나(노션 · 옵시디언 · 종이 · 보고서 서랍)? 서랍이면 작업대와 연결이 필요하다.
2. 컴퓨터 앞에서 작업대를 어떻게 연다고 상상하나(홈 타일 · 사이드바 · 즐겨찾기)? 열기까지 탭 수가 착수를 좌우한다.
3. 작업대에 동시에 몇 개를 올려 둘 것 같은가? 5개쯤에서 상한을 둘지.
4. "앉은 지 n분"을 실제로 보고 싶은가, 아니면 "N분만 해 보자"가 더 맞는가?
5. 학원 상담 내용(학생 이름 등)을 메모에 적을 것인가? 저장 · 공유 정책이 필요하다.
6. 반복 규칙의 단계를 작업대에서 고치고 "앞으로도"에 반영하고 싶은 일이 얼마나 되나?
7. 진행 막대와 "2/5" 중 하나만 둬도 되나?
8. 매주 "이번 주 한 일" 보고서를 Claude 가 자동으로 써 주길 원하나?
