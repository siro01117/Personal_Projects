# 보고서 서랍 — 설계서 v1

> EZ.WORK 첫 삽. 에이전트(Claude Code)가 MCP 로 서칭 보고서를 **블록으로 조립**해 넣고, 사람은 **윈도우 탐색기처럼** 폴더로 정리하고 읽는다.
> 2026-09-30 작성. 로컬에서 만들고, 일정까지 끝나면 배포.

## 0. 정해진 것 (노션 답변·목업 피드백)

- 이름 EZ.WORK · 라칸 재사용 안 함(가져갈 것은 일정 규칙·데이터뿐, 이 단계와 무관)
- 보고서 = **블록 조립만**. HTML 통째 올리기 없음
- 보고서 종류 = 서칭 보고서 3종: 작업 방식 조사 · 데이터 조사 · 레퍼런스 조사
- 사람은 **글자만** 고친다. 블록 구조(종류·개수·순서·표 칸 수)는 안 바뀐다
- 로그인 없이 **읽기 전용 공유 링크**
- MCP 는 **내 PC 에서 Claude Code 가 실행하는 로컬 방식**. 별도 서버 없음
- 화면: 미니멀 1차 · 키위 포인트 · 데스크톱 폭 전체 · 가운데 큰 아이콘 · 탐색기(선택/열기/우클릭/끌어 옮기기/되돌리기)

## 1. 구성

```
ez-work/
  lib/        블록 스키마·이름 규칙·경로 — 웹과 MCP 가 같이 씀 (한 곳에서만 정의)
  app/        Next.js 웹 (로그인 · 홈 · 탐색기 · 보고서 · 공유 페이지)
  mcp/        로컬 MCP 서버 (stdio) — Claude Code 가 실행
  db/         SQL 마이그레이션 + PGlite 로 도는 DB 테스트
  docs/       이 문서
```

- 데이터: RA-KAN Supabase 프로젝트 안, **`ez_` 로 시작하는 테이블만**. 일정(`kv`)은 손대지 않음
  - Supabase 는 새 스키마를 쓰려면 대시보드에서 따로 열어야 해서, 같은 효과를 접두사로 낸다. 나중에 싹 밀 때 `ez_*` 가 아닌 것을 지우면 된다
- 로그인: RA-KAN 의 Supabase Auth 계정 그대로
- 테스트 DB: **PGlite**(브라우저·Node 에서 도는 Postgres). 도커 없이 트리거·제약을 진짜 Postgres 로 시험한다

## 2. 데이터 — 테이블 하나 `ez_items`

폴더와 보고서를 **한 테이블**에 둔다. 윈도우처럼 한 폴더 안에서 폴더·파일 이름이 서로 겹치면 안 되는데, 테이블이 하나여야 그걸 인덱스 하나로 막을 수 있다.

| 열 | 뜻 |
|---|---|
| `id` uuid | |
| `owner` uuid | auth 사용자 |
| `parent_id` uuid? | 담긴 폴더. 없으면 서랍 맨 위 |
| `kind` | `folder` / `report` |
| `name` | 폴더 이름 = 보고서 제목 |
| `report_kind` | `method` / `data` / `reference` (보고서만) |
| `blocks` jsonb | 블록 배열 (보고서만) |
| `schema_version` int | 블록 어휘 버전. 지금 1 |
| `agent` text | 쓴 에이전트 이름 (`Claude Code`) |
| `version` int | 고칠 때마다 +1. 동시 수정 충돌 감지용 |
| `agent_updated_at` | 에이전트가 마지막으로 쓴 시각 |
| `read_at` | 내가 마지막으로 연 시각. `agent_updated_at > read_at` 이면 안 읽음 |
| `share_token` text? | 공유 링크 열쇠. 없으면 비공개 |
| `deleted_at`, `deleted_batch` | 지운 것(휴지통). 같이 지운 묶음 id |
| `created_at`, `updated_at` | |

DB 가 막는 것 (웹·MCP 어느 쪽 실수든 여기서 걸린다):
- 같은 폴더 안 같은 이름 — 대소문자·앞뒤 공백 무시, 지운 것은 제외 (부분 유일 인덱스)
- 이름: 앞뒤 공백 제거 후 1~100자, `/` 금지(MCP 경로 구분자), 줄바꿈·제어문자 금지
- `parent_id` 는 **살아 있는 폴더**만
- 자기 자신·자기 자손 안으로 옮기기 금지 (순환)
- 폴더 깊이 최대 8단
- 보고서만 `blocks` 를 가짐, 폴더는 `blocks` 없음
- `blocks` 크기 상한 600KB
- 다른 사람 것은 못 봄·못 고침 (RLS: `owner = auth.uid()`)

## 3. 블록 어휘 v1

서칭 보고서의 뼈대에서 뽑았다. `lib/blocks.ts` 한 곳에서 zod 로 정의하고, MCP 는 넣기 전에 검사한다.

| 종류 | 필드 | 규칙 |
|---|---|---|
| `verdict` 판정 | `v` 한 줄, `w?` 풀이 | 보고서당 최대 1개 |
| `text` 문단 | `h?`, `body` | body ≤ 4,000자 |
| `list` 목록 | `h`, `items[]` | 1~30개, 각 ≤ 600자 |
| `table` 표 | `h`, `cols[]`, `rows[][]` | 열 2~8, 행 1~60, **모든 행의 칸 수 = 열 수**, 칸 ≤ 300자 |
  - 그릴 때 **첫 열이 바로 위 행과 같으면 한 칸으로 합친다**(rowSpan, 2026-10-04). 데이터는 그대로 반복해 두고 화면만 합친다 — 빈 칸은 안 합치고, 고치기 모드에서는 칸마다 고칠 수 있게 안 합친다. 좁은 폭(행이 카드)에서는 카드마다 제목이 다시 보인다. Markdown 복사는 반복 그대로
| `claims` 근거 | `h`, `items[{tag,text,refs[]}]` | tag = `fact`(사실) / `guess`(추정). refs 는 출처 번호(1부터) — **출처 범위 밖 번호 금지** |
| `sources` 출처 | `h`, `items[{title,url}]` | 보고서당 최대 1개, 1~100개, **url 은 http/https 만** |

- 보고서당 블록 1~200개
- 검사 실패 시 에이전트가 고칠 수 있게 **위치와 이유**를 돌려준다
  예: `blocks[2].rows[3]: 칸이 3개인데 열은 4개입니다`
- 화면은 **모르는 블록 종류를 만나도 깨지지 않는다** — "이 블록은 아직 볼 수 없습니다" 자리표시
- 글자는 전부 텍스트로만 그린다(HTML 해석 안 함) → 보고서 안 문자열로 스크립트가 못 들어온다

### 사람이 고칠 수 있는 칸

문자열 칸 중 아래만. 그 외(`type`, `tag`, `url`, `refs`, 칸 수)는 손으로 안 바뀜.

`verdict.v/w` · `text.h/body` · `list.h/items[i]` · `table.h/cols[i]/rows[i][j]` · `claims.h/items[i].text` · `sources.h/items[i].title` · 보고서 제목

- DB 함수 `ez_edit_text(id, base_version, path, value)` 가 **그 자리가 원래 문자열인지, 허용된 칸인지** 확인하고 바꾼다
- 길이 상한은 블록 규칙과 같음
- **빈칸으로 둘 수 있다** (2026-10-02 바꿈 — 처음엔 빈 값 금지였다). 보고서 제목만 비울 수 없다
  - 비운 칸은 읽을 때 안 보인다: 소제목은 줄째 사라지고, 목록 항목 · 근거 줄 · 문단은 그 줄이 빠지고, 표 칸은 빈 칸으로, 출처 제목을 비우면 주소가 대신 보인다
  - 글자 고치기 모드에서는 비운 칸이 옅은 자리표시로 남아 다시 채울 수 있다. 글자를 비운다고 블록이 없어지지는 않는다(블록 지우기 · 옮기기는 아래 절)
  - 에이전트가 새로 넣는 글자는 지금처럼 비면 안 된다(`report_create` 와 `report_edit` 로 넣는 블록). 사람이 비워 둔 칸은 에이전트가 그 보고서를 고칠 때 검사에 걸리지 않는다
- **줄바꿈**(2026-10-02): 고치는 칸에서 **Enter 는 저장, Shift+Enter 는 줄바꿈**(Ctrl/⌘+Enter 도 저장). 전에는 문단·판정 풀이만 Enter 로 줄바꿈이 됐다. 줄바꿈이 되는 칸: 문단 · 판정 풀이 · 목록 항목 · 표 칸(머리 제외) · 근거 글. 한 줄 칸(줄바꿈 안 됨): 보고서 제목 · 작성자 · 소제목 · 판정 한 줄 · 표 머리 · 출처 제목 · 사진 설명과 캡션. 읽을 때 줄바꿈은 그대로 줄이 바뀌어 보인다
- **작성자**(제목 아래 "Claude Code · 오늘" 의 앞부분)도 고칠 수 있다. 1~100자, 비우면 날짜만 보인다. 날짜는 자동이라 못 고친다. 에이전트가 그 보고서를 다시 고치면 작성자는 에이전트 이름으로 돌아간다

### 사람이 블록을 고르고 · 지우고 · 옮기기 (2026-10-02)

글자 고치기 모드(연필)에서만. 블록 **안의 내용**(종류 · 칸 수 · 출처 주소)은 여전히 손으로 안 바뀌고, 블록 **통째로** 빼거나 순서를 바꾸는 것만 된다. 새 블록 넣기는 에이전트 몫 그대로.

**고르기**
- 끌기: 한 블록에서 누른 채 다른 블록으로 넘어가면 글자 선택이 풀리고 **시작 블록 ~ 지금 블록**이 통째로 골라진다(노션 방식). 블록 사이 빈 곳 · 옆 여백에서 시작해도 같다. 한 블록 안에서만 끌면 평소처럼 글자 선택
- 손잡이(고치기 모드에서 블록 왼쪽에 보이는 점 여섯 개): 누르면 그 블록만 고름, Shift+누르기 = 범위, Ctrl/⌘+누르기 = 하나씩 더하고 빼기. 터치는 손잡이를 누를 때마다 더하고 빼기
- Ctrl/⌘+A: 칸 안에 커서가 없을 때 전부 고름(칸 안에서는 그 칸의 글자 전체 — 평소대로). Esc · 빈 곳 누르기 · 고치기 모드 끄기 = 고르기 풀림
- 제목 · 작성자 줄은 블록이 아니라 고를 수 없다
- 고른 블록은 키위 옅은 바탕 하나로만 표시(라벨 · 개수 표시 없음)

**지우기**
- 고른 상태에서 Delete / Backspace(칸 안에 커서가 없을 때), 또는 아래 "고치기 도구 줄" 의 휴지통
- 전부 지울 수는 없다 — 하나는 남아야 한다: "블록이 하나는 남아야 합니다"
- 알림에 "되돌리기". **실제 저장은 알림이 사라질 때**(약 6초) 한다 — 그 전에 다른 고치기 · 옮기기를 하거나 고치기 모드를 끄거나 화면을 떠나면 그때 바로 저장. 창을 그냥 닫으면 안 지워진 채로 남는다(안전한 쪽)
- 출처 블록을 지우면 근거 블록들의 출처 번호(`refs`)는 비워지고 사진 블록의 `ref` 도 빠진다(가리킬 곳이 없어지므로). 사진 블록을 지우면 그 사진 파일은 기존 사진 청소 규칙을 따른다

**옮기기**
- 손잡이를 끌면 옮겨진다. 고른 블록의 손잡이를 끌면 **고른 것 전부**가 원래 순서대로 한 덩어리로 간다. 놓일 자리는 블록 사이의 키위 선
- 키보드: 고른 상태에서 Alt+↑ / Alt+↓ 한 칸씩
- 터치: 손잡이를 길게 눌러 끌기
- 나머지 블록은 자리를 비켜 주는 모션(`docs/모션.md` 의 목록 재배치). 화면 끝 가까이 끌면 스크롤
- 옮긴 뒤 알림 없음(다시 끌면 되니까)

**저장**
- DB 함수 `ez_blocks_arrange(id, base_version, order int[])` 하나 — `order` 는 새 순서로 늘어놓은 **옛 블록 번호**(0부터). 빠진 번호 = 지움. 번호가 겹치거나 범위 밖이거나 비어 있으면 거절. 내용은 건드릴 수 없는 모양이라 "블록 안은 손으로 안 바뀐다" 가 그대로 지켜진다
- 버전 불일치는 글자 고치기와 같은 흐름("방금 다른 곳에서 이 보고서를 고쳤습니다")
- 차례 레일과 `#b번호` 는 새 순서를 따른다

### 고치기 도구 줄 (2026-10-02)

고치기 모드에서는 **종이 왼쪽 바깥에 세로로 서서 따라오는 도구 줄** 하나가 있다(스크롤해도 화면 가운데 높이에 머문다). 읽기 모드에서는 아무것도 뜨지 않는다. 처음엔 아래 가운데 가로 줄에 되돌리기 · 전부 고르기도 있었는데 뺐다 — 그 둘은 키(Ctrl/⌘+Z, Ctrl/⌘+A)로만.

위부터, 전부 아이콘만(글자 · 개수 표시 없음, 이름은 `title` / `aria-label` 로):

| 단추 | 하는 일 | 못 누를 때(흐리게) |
|---|---|---|
| 휴지통 | 고른 블록 지우기 | 고른 게 없을 때 |
| 위로 · 아래로 | 고른 블록을 한 칸씩 (Alt+↑/↓ 와 같다) | 고른 게 없거나 끝에 닿았을 때 |
| 완료 | 고치기 모드 끄기 (키위 포인트). **Esc** 도 같다 — 고른 게 있으면 먼저 풀고, 한 번 더 누르면 끈다 | — |

- 모양: 종이색 바탕 · 테두리 · 옅은 그림자의 둥근 알약 하나(어두울 때는 한 단 밝은 면). 검은 바탕 금지. 단추 44px
- 종이 왼쪽에 자리가 없는 폭(좁은 창 · 폰)에서는 **오른쪽 아래**에 세로로 뜬다 — 왼쪽 여백은 손잡이 자리라서. 알림보다 위

**되돌리기가 기억하는 것** (이 화면을 연 동안, 고치기 모드를 꺼도 유지 · 보고서를 새로 불러오면 비움)
- 글자 고치기 → 원래 글자로 다시 저장
- 블록 옮기기 → 거꾸로 옮겨 저장
- 블록 지우기 → 아직 저장 전(알림이 떠 있는 6초)이면 그대로 살림. **이미 저장된 지우기는 되돌릴 수 없고**, 그때 그 앞의 기록도 같이 비운다(번호가 달라져서)
- 다시 하기(redo)는 없다

## 4. MCP 도구 (6개)

도구 설명은 매번 Claude Code 컨텍스트에 실리므로 **개수를 줄였다**. 경로는 `/` 로 시작: `/`(맨 위), `/EZ.WORK 준비/APPTIVE`.

| 도구 | 하는 일 | 엣지 |
|---|---|---|
| `drawer_list(path?, query?)` | 폴더 안 목록(폴더 먼저, 각각 이름순 — `localeCompare('ko')` 라 한글이 영문보다 앞). `query` 를 주면 제목·본문 찾기: `path` 를 같이 주면 그 폴더 아래(자손 포함)로 좁힘, 최대 20개, 각 결과에 `match`(`name`/`body`)와 본문 맞은 자리 앞뒤 약 40자 `snippet`. DB 함수 `ez_search` 가 보고서 안 사용자 글자(문자열 값, `type`·`tag`·`url` 제외)만 찾는다 | 없는 경로 → 오류 + 가장 가까운 폴더 제안 |
| `drawer_mkdir(path)` | 폴더 만들기, 중간 폴더도 | 이미 있으면 그대로 성공. 중간에 실패하면(깊이 등) 이번에 만든 폴더만 되돌림 |
| `drawer_update(target, move_to?, rename?, delete?)` | 옮기기 · 이름 바꾸기 · 휴지통으로 | 옮기기: 순환·삭제된 폴더 금지, 이름 겹치면 `(2)`. 이름 바꾸기: 겹치면 거절(사람이 정한 이름이라 자동 변경 안 함) |
| `report_create(title, kind, folder, blocks)` | 보고서 넣기. **도구 설명에 블록 어휘 요약을 담는다** | 검사 실패 → 위치·이유 목록. 제목 겹치면 `(2)` 붙이고 알려줌 |
| `report_get(id, from?, to?)` | 보고서 읽기, **블록 범위만 가능** | 범위 없으면 차례 + 판정만(통째로 먹이지 않음) |
| `report_edit(id, base_version, ops[])` | 블록 넣기·바꾸기·빼기 | `base_version` 이 낡았으면 충돌 + 현재 버전 반환 |

- `target` 은 id 또는 경로
- 인증: `.env.local` 의 service role 키 + 내 사용자 id. 이 PC 에서만 돈다
- 에이전트가 쓰면 `agent_updated_at` 갱신 → 서랍에 안 읽음 점

## 5. 화면 동작

**탐색기**
- 폴더 먼저, 그다음 보고서. 각각 이름순(한국어 정렬 — 한글이 영문보다 앞)
- **한 번 누르면 열기**(2026-10-02 바꿈 — 전에는 한 번 = 선택, 두 번 = 열기). 고르기는 Shift · Ctrl 누르기 또는 메뉴의 "선택"
- 우클릭 / 길게 누르기 메뉴: 열기 · 이름 바꾸기 · 옮기기 · 공유 · 삭제. 빈 곳: 새 폴더
  - 옮기기 = 옮길 폴더 목록(목업 방식). 공유 = 그 보고서를 열고 공유 창을 띄움(폴더는 공유 없음)
- 끌어 놓기: 폴더 위, 또는 위쪽 경로 위. 자기 자신·현재 폴더 위는 무동작
- 옮긴 뒤 알림에도 "되돌리기"(원래 폴더로 다시 옮김, 목업대로)
- 새 폴더: 빈 이름 `새 폴더`, 겹치면 `새 폴더 (2)`, 만들자마자 이름 입력
- 키보드: 화살표 · Enter · F2 · Delete · Backspace(상위) · Esc(취소)
- 경로가 길면 가운데를 `…` 로 접음
- 빈 폴더: "빈 폴더" 한 줄

**이름 바꾸기**
- Enter 저장 · Esc 취소 · 다른 곳 누르면 저장
- **한글 조합 중 Enter 는 무시**(`isComposing`) — 안 그러면 마지막 글자가 잘리거나 두 번 저장됨
- 겹치는 이름 → 입력 유지하고 "같은 이름이 이미 있습니다"
- 앞뒤 공백 자동 제거, 빈 이름이면 취소

**삭제·되돌리기**
- 삭제는 휴지통으로(바로 사라지지 않음). 폴더를 지우면 안의 것도 같은 묶음으로
- 알림의 "되돌리기" = 묶음째 복원
- 복원할 자리의 폴더가 그 사이 지워졌으면 **서랍 맨 위로** 복원하고 알림
- 복원할 이름이 그 사이 생긴 것과 겹치면 `(2)` 붙여 복원
- 휴지통 화면은 7-1장. 지운 지 14일 지나면 자동 영구 삭제(7-2장)

**보고서**
- 블록을 그린다. 오른쪽 레일 = 차례(넓을 때만)
- 연필 = 글자 고치기 모드. 블록 경계가 보이고 글자 칸만 고칠 수 있음
- 저장은 칸에서 벗어날 때. 실패하면 원래 글자로 되돌리고 알림
- **동시 수정**: 그 사이 다른 곳(에이전트·다른 창)에서 고쳤으면(버전 불일치) "방금 다른 곳에서 이 보고서를 고쳤습니다" + "새로 불러오기". DB 는 누가 고쳤는지 알려주지 않는다
- 열면 읽음 처리

**공유**
- 공유 켜기 → 링크 생성(추측 불가 22자). 끄기 → 링크 무효. 다시 켜면 **새 링크**(옛 링크 계속 무효)
- 공유 페이지 `/s/[열쇠]`: 로그인 없이, 읽기만, 검색엔진 차단(noindex)
- 지운 보고서·꺼진 링크 → "없는 링크입니다" (있었는지 여부를 드러내지 않음)
- DB 함수 `ez_shared(token)` 로만 읽음. 웹에 service role 키를 두지 않는다

**공통**
- 저장은 화면을 먼저 바꾸고(낙관적), 실패하면 되돌리고 알림
- 로그인 풀림 → 로그인 화면, 돌아오면 있던 자리로
- 모바일: 탐색기 3열, 끌어 놓기 대신 메뉴의 "옮기기"

## 7-1. 4단계 — 레퍼런스 비교로 더하는 것 (2026-09-30)

근거: `docs/레퍼런스-비교.md`. 기준은 "없으면 매일 쓰는 데 막히는가" + 윈도우 탐색기 기본기.

**꼭 넣을 것**
1. MCP 결과에 웹 링크(`EZ_WEB_URL`, 기본 `http://localhost:3200`)
2. 인용 번호 → 출처로 이동, 올리거나 초점 두면 출처 제목·도메인 미리보기
3. 공개 중 표시 — 탐색기에서 공유 켜진 보고서에 작은 표시
4. 폴더에 안 읽음 전파 — 안(자손)에 안 읽은 보고서가 있으면 폴더에도 점
5. 찾기 화면 — 위쪽 줄 검색, `ez_search`
6. Markdown 으로 복사 — `lib` 순수 함수(웹·MCP 공용)
7. 휴지통 화면 — 지운 묶음 목록, 묶음 복원

**탐색기 기본기**
- 여러 개 선택: Ctrl·Shift 클릭, Ctrl+A, Esc 로 해제. 선택한 것들에 옮기기·복사·삭제가 한 번에
- 복사 Ctrl+C · 잘라내기 Ctrl+X · 붙여넣기 Ctrl+V. 복제는 메뉴 '사본 만들기' 또는 같은 폴더에 Ctrl+C → Ctrl+V. **Ctrl+D 단축키는 두지 않는다** — 윈도우 탐색기에서 Ctrl+D 는 삭제라 뜻이 반대가 되고, 브라우저 즐겨찾기도 막는다
- 실행취소 Ctrl+Z — 이 세션에서 한 마지막 작업(옮기기·이름·삭제·복사·새 폴더)을 되돌림. 알림의 '되돌리기'와 같은 동작
- 정렬: 이름순 / 날짜순. 날짜순이어도 폴더 먼저, 폴더끼리는 이름순, 보고서끼리만 최근 고친 것 먼저. 선택은 기기에 기억
- 휴지통 묶음 이름: 첫 맨 위 항목 이름 + "외 N개"(N = 나머지 맨 위 항목 수, 자손은 세지 않음). 맨 위 항목이 하나면 이름만
- 폰 폭(사이드바가 숨는 폭)에서는 서랍 맨 위 화면 위쪽 줄에 휴지통 버튼. 넓은 폭은 사이드바의 '휴지통' 한 줄만

**복사 규칙**
- 이름: `이름 - 복사본`, 겹치면 `이름 - 복사본 (2)` (윈도우와 같음). 다른 폴더에 붙여 넣을 때 겹치지 않으면 이름 그대로
- 복사본: 공유 끔(`share_token` 없음), 안 읽음 아님, `agent` 는 원본 그대로, version 1
- 폴더 복사는 안의 것까지 통째로. 깊이 초과·실패 시 **전부 취소**(한 트랜잭션) — DB 함수 `ez_copy`
- 여러 개를 지우면 **한 묶음**으로(되돌리기 한 번에) — DB 함수 `ez_delete_many`
- 폴더를 자기 안에 붙여 넣기(순환) 금지

**조정**
- 차례 레일: 블록 8개 이상일 때만

## 7-2. 5단계 (2026-09-30 결정)

**넣는 것**
1. **사진 블록** — 8-1장 그대로. 배치(좌·우·크기)는 에이전트만 정한다(손으로 바꾸기는 미정 — 이번엔 안 넣음). 사진 설명(alt)·캡션 글자는 사람이 고칠 수 있음
2. **휴지통 자동 비우기 — 2주**. 지운 지 14일 지난 묶음은 영구 삭제. 매일 한 번(pg_cron). 사진 파일 정리는 8-1장 방식
3. **신선도 — 표시만**. 보고서 머리와 목록에 "n일 전"(에이전트가 마지막으로 쓴 때 기준). 색·경고·다시 조사 버튼 없음
4. **목록 보기** — 아이콘 보기 ↔ 목록 보기 전환(기기에 기억). 목록 열: 이름 · 종류 · 고친 때. 선택·키보드·끌어 놓기·우클릭은 아이콘 보기와 같게

**만든 규칙** (5단계 구현 때 정함)
- 휴지통 비우기: DB 함수 `ez_purge_trash(14)` 를 pg_cron 이 매일 03:17(UTC)에 부른다. 묶음의 지운 때는 가장 늦은 `deleted_at`. 안에 남은 행이 없는 것부터 한 겹씩 지운다 — 안에 아직 안 지난 묶음이 있는 폴더는 다음 회차로
- 신선도 "n일 전": 오늘 · 어제 · n일 전(2~6) · n주 전(1~3) · 그보다 오래면 날짜. 달력 날짜로 센다
- 목록 보기 '고친 때' = 날짜순 정렬 값: 보고서는 `agent_updated_at`(없으면 `created_at`), 폴더는 `updated_at`. 날짜순이어도 폴더끼리는 이름순이라 실제로는 보고서끼리만 이 값으로. 칸 이름 줄(이름·종류·고친 때)은 윈도우 자세히 보기처럼 둔다. 폰 폭은 종류 열 숨김, 목록 보기에서 좌우 화살표는 무동작
- 찾기 결과·휴지통 화면은 목록 보기와 무관하게 지금 모양

**뺀 것**
- 조사 요청함 — 안 함
- 보고서 → 할 일 보내기 — 안 함. 대신 **나중에 프로젝트 모듈에서 보고서를 링크**할 수 있게(프로젝트 설계 때)

## 7-3. 보고서 화면 다시 잡기 (2026-10-01 피드백)

**원칙**
- **검은 배경을 쓰지 않는다.** 판정도 어두운 카드 대신 **섹션 구분**(여백·가는 선·제목)으로 나눈다
- **강조 = 굵게 + 진한 색** (2026-10-01 결정. 초록 형광펜·크기 키우기·숫자 따로 표시는 비교 후 뺐다)
  - 본문은 한 단계 연한 색(`--text-2`), 강조는 가장 진한 색(`--text-1`) + 굵게. 배경·밑줄·포인트색 없음 — 볼트 원칙 "위계는 두께·색을 함께"
  - 판정 한 줄도 같은 방식, 크기는 본문과 같게. 맨 위 위치와 여백으로 구분
  - 글 안의 강조: 문자열 속 `==강조할 글==`. HTML 해석은 여전히 없음(구분자만 나눠 그림). Markdown 복사에서는 `**…**`
  - 글자 고치기 모드에서는 `==` 표시가 그대로 보인다(고칠 수 있게)
- **좁게 읽는다**: 데스크톱이라도 보고서 폭을 넓히지 않는다. 읽는 폭 상한 약 **920px**, 가운데. 넓은 화면의 남는 자리는 비워 둔다(차례 레일은 그대로 바깥에)
- **글씨 1.3배**: 본문 14 → 18px, 소제목·제목·메타도 같은 비율
- **블록은 직관적인 배치 — 한 행에 객체 최대 2개**(사진·글을 각각 객체로 본다)
  - 사진 `place: left | right` = 바로 **다음 블록 하나와 짝**을 지어 2칸 행. `size` 가 사진 칸의 비율(1/3·1/2·2/3), 나머지가 글 칸
  - 짝이 될 수 있는 다음 블록: 문단·목록·근거. 표·판정·출처·다른 사진이면 짝 없이 사진만 그 크기로 한쪽에 선다
  - 글이 사진 아래로 흘러 내려가지 않는다(어울림 대신 칸) — 3개가 한 행에 서는 일이 구조적으로 없다
  - `full` 은 행 하나를 혼자 쓴다
  - 폰(좁은 폭): 2칸 행은 위아래로 — 순서는 데이터 순서 그대로. 비율로 나눈 칸이라 폰으로 옮기기 쉽다
- **간격**: 행과 행 사이, 사진과 위 객체 사이를 넉넉히(붙어 보이지 않게)
- **종이와 바탕** (2026-10-01): 문서 앱처럼 양옆은 회색 바탕(`--canvas`), 글은 가운데 흰 종이(`--paper`, 얇은 테두리) 위. 글 폭 920px 는 그대로, 종이는 안쪽 여백만큼 넓다. 폰에서는 회색 없이 종이가 화면 전체

**구현하며 정한 규칙**
- `==…==` 는 `lib/marks.ts` 가 나눈다: 여는 `==` 뒤 가장 가까운 `==` 가 짝. 짝이 없거나 줄을 넘으면 글자 그대로, 빈 강조(`====`)도 글자 그대로. 보고서 제목·사진 설명(alt)에는 적용하지 않는다. 판정 한 줄은 이미 굵어서 Markdown 에서는 표시만 뺀다. 차례·인용 미리보기·사진 출처 줄도 표시를 뺀다
- 행 묶기는 `app/_logic/rows.ts` 순수 함수. 짝이 될 다음 블록이 모르는 블록·깨진 블록이면 짝 없이 혼자. 글 하나는 한 번만 짝이 된다(사진-글-글 → 둘째 글은 혼자)
- 소제목이 있는 블록으로 시작하는 행 위에만 가는 선(판정·사진만 있는 행·제목 없는 문단은 선 없음). 표 테두리는 그대로
- 글 폭 상한(72ch)은 없앤다 — 본문 920px 이 상한이고, 2칸 행의 글 칸은 칸을 채운다
- 차례 레일은 본문 바깥 오른쪽 168px. 본문 가운데를 지키면서 레일이 들어갈 자리(본문 영역 1,328px 이상)가 없으면 숨긴다

## 7-4. 읽은 사람 (2026-10-03, 피드백 반영 v2)

> 공유 링크로 **누가 봤는지 · 얼마나 읽었는지**, 그리고 **지금 누가 어디를 보고 있는지**(피그마의 아바타 · 커서처럼) 주인 화면에서 보고 싶다.

**이름은 안 적어도 된다.** 안 적으면 그 보고서에 처음 온 순서대로 **게스트 1 · 게스트 2 …** 로 부른다(번호는 보고서마다, 기기마다 하나). 공유 페이지 맨 아래 작은 글자 "이름 적기" 로 언제든 바꿀 수 있고, 그 기기에 기억한다. 이름 칸이 읽기를 막지 않는다 — 처음 열면 바로 보고서다.

### 두 층

| | 무엇 | 어떻게 | 남는가 |
|---|---|---|---|
| **기록** | 누가 · 처음 · 마지막 · 몇 번 · **읽은 시간** | DB `ez_views`, anon 함수로 적는다 | 남는다 |
| **라이브** | 지금 누가 · **어느 블록을 보고 있나** | Supabase Realtime **presence** 채널(`report:<열쇠>`), DB 를 거치지 않는다 | 안 남는다 |

라이브가 끊겨도(채널 실패) 기록은 핑으로 쌓이고, 주인 화면은 핑 기준(70초 안)으로라도 "지금 보는 중" 을 보여 준다.

### 기록 `ez_views` — 보고서 × 기기마다 한 줄

| 칸 | 규칙 |
|---|---|
| `id` `item_id` → `ez_items` on delete cascade | |
| `device` | 기기 열쇠. 공개 페이지가 처음 열릴 때 만들어 `localStorage` 에 둔 22자 무작위 글자 |
| `guest_no` | 그 보고서에서 몇 번째 기기인지(1부터). 함수가 매긴다 — "게스트 n" 의 n |
| `name` | 적은 이름(null 가능), 1~20자 |
| `first_at` `last_at` | 처음 본 때 · 마지막으로 살아 있던 때 |
| `hits` | 들어온 횟수(페이지를 연 횟수. 핑은 세지 않는다) |
| `seconds` | **읽은 시간**(초). 보고서가 **보이는 동안**만 센다 — 핑마다 지난 핑 이후 보인 초를 더한다(한 핑에 최대 60초. 탭이 숨겨져 있던 시간은 안 들어간다) |
| `ua` | 기기 힌트 한 줄("폰 · Safari", "PC · Chrome"), ≤ 80자 |

- 주인 본인(공유 페이지에 로그인 세션이 그 주인)은 적지 않는다
- 보고서당 500줄까지. 넘으면 가장 오래된 `last_at` 줄을 지운다
- 영구 삭제하면 같이 지워진다(cascade). 공유를 끄고 다시 켜도 기록은 남는다(링크가 아니라 보고서에 붙는다)

**함수 (anon)** — security definer, anon 에게는 이 셋만. 없는 열쇠 · 꺼진 링크 → 빈 결과(있었는지 드러내지 않음)
| 함수 | 하는 일 |
|---|---|
| `ez_view_open(token, device, ua)` | 들어옴. 줄이 없으면 만들고(`guest_no` 매김, `hits=1`), 있으면 `ua` · `last_at` 갱신 + `hits+1`. 돌려주는 것: `guest_no` · `name` (화면이 "게스트 n" 또는 이름을 안다) |
| `ez_view_ping(token, device, seen_sec)` | 살아 있음. `last_at = now()`, `seconds += least(seen_sec, 60)`. 보이는 동안 **30초마다**, 숨겨지면 멈추고 돌아오면 바로 한 번, 떠날 때 `sendBeacon` 으로 마지막 한 번 |
| `ez_view_name(token, device, name)` | 이름 적기 · 바꾸기(빈 값이면 다시 게스트 n) |

### 라이브 — presence

- 채널 `report:<열쇠>`. 공개 페이지는 **보이는 동안** 들어가 있고(숨겨지면 나간다), 상태로 `{device, label, block}` 을 둔다 — `label` 은 이름 또는 "게스트 n", `block` 은 **화면 가운데에 걸린 블록 번호**(스크롤 멈춘 뒤 300ms, 바뀔 때만 track)
- 주인 화면(`/drawer/r/[id]`)만 같은 채널을 **듣는다**(자기 상태는 올리지 않는다). 공개 페이지끼리는 서로 안 보인다 — 공개 페이지는 presence 상태를 읽지 않는다(Realtime 채널은 공개라 기술적으로는 읽을 수 있다. 1차에서는 화면이 안 보여 주는 것으로 둔다. 라이브에 올리는 것은 라벨과 블록 번호뿐이다)
- Realtime 이 안 되면(연결 실패 · 끊김) 주인 화면은 기록의 70초 판정으로 "지금 보는 중" 만 보여 주고 위치는 없다

### 주인 화면 (`/drawer/r/[id]`)

- 위쪽 도구 줄에 **보는 사람들** — 피그마처럼 **동그란 아바타 줄**(이름 첫 글자, 키위 바탕의 농담을 사람마다 조금 다르게. 4명 넘으면 `+n`). 아무도 없으면 눈 아이콘만
- **블록 옆 표시**: 지금 보는 사람이 있는 블록의 왼쪽 여백에 그 사람의 작은 아바타(여럿이면 겹침). 오른쪽 차례 레일에도 그 항목 옆에 점. 스크롤에 따라 부드럽게 옮겨 간다(`docs/모션.md`, transform 만)
- 아바타 줄이나 눈을 누르면 작은 창(공유 창과 같은 모양):
  - 지금 보는 중 — 라벨 · 보고 있는 블록 제목
  - 본 사람 — 라벨 · 마지막으로 본 때 · 읽은 시간(분, 1분 미만은 "1분 미만") · 횟수. 최근 것부터, 20줄 넘으면 "더 보기"
  - 아무도 안 봤으면 "아직 아무도 안 봤습니다"
- 기록은 보고서를 열어 둔 동안 30초마다 다시 읽는다(탭이 숨겨지면 멈춤). 라이브는 presence 이벤트로 바로
- 탐색기 줄에는 아무것도 더하지 않는다(미니멀)

### 공개 페이지 (`/s/[열쇠]`)

- 처음 열면 바로 보고서. 조용히 `ez_view_open` → 채널 들어가기 → 핑
- 맨 아래 작은 글자: "이름 적기"(이미 적었으면 그 이름 · "바꾸기"). 한글 조합 중 Enter 무시
- 다른 사람이 보고 있다는 것은 보여 주지 않는다

### 구현하며 정한 규칙 (2026-10-03)
- 게스트 번호는 보조 테이블 `ez_view_seq`(보고서마다 마지막 번호, 아무에게도 안 연다)가 센다 — `max + 1` 이면 500줄 상한으로 지워진 뒤 번호가 다시 쓰여서. 번호는 upsert 한 줄로 매겨 동시에 와도 안 겹친다
- 떠날 때의 마지막 핑은 `sendBeacon` 이 아니라 **`fetch(…, { keepalive: true })`** 로 — `sendBeacon` 은 `apikey` 헤더를 못 붙인다. REST `rpc/ez_view_ping` 주소로 anon 키만 싣고 바로 보낸다(주인 본인 줄은 애초에 없어 바뀌는 게 없다)
- 공개 페이지의 적기 함수 셋은 **세션 클라이언트**로 부른다 — 로그인해 있으면 세션이 같이 가서 DB 가 `auth.uid() = owner` 로 주인을 건너뛴다. 세션이 없으면 anon 키만 가니 anon 이다. `ez_shared` 는 전처럼 anon 클라이언트
- 기기 열쇠는 링크마다가 아니라 기기에 하나(`localStorage` `ezwork.device`). 이름은 서버 줄에 있으니 기기에는 두지 않는다 — `ez_view_open` 이 돌려준다
- 핑의 "보인 초" 는 마지막 핑(또는 보이기 시작) 이후 지난 초, 60초로 자른다. 숨겨질 때 그때까지의 초를 한 번 보내고 멈춘다. 돌아오면 0초로 한 번(살아 있음만)
- presence 로 받은 상태는 남이 올린 것이라 모양을 검사한다: 기기 22자 · 라벨 글자(24자로 자름) · 블록은 0 이상 정수. 같은 기기가 두 탭이면 마지막 것 하나
- 블록 왼쪽 아바타는 블록 번호가 보고서 범위 안일 때만. 데스크톱은 같은 블록 사람들을 옆으로 12px 씩 겹치고, 폰(왼쪽 여백 16px)은 아래로 14px 씩 쌓는다
- 지금 보는 중 목록의 순서는 라벨순(한국어 · 숫자는 수로 — 게스트 2 가 게스트 10 앞)
- 확인 모드(`?demo=1`)는 메모리라 새로 고치면 기록이 처음으로 돌아간다(이름도). 라이브는 표본 둘 — 게스트 2 는 5초마다 다음 블록으로 옮겨 간다
- 차례 레일의 점은 보는 블록이 속한 절(그 번호 이하 가장 가까운 차례 항목)에 찍는다

## 7-5. 방명록 · 댓글 · 방문 기록 (2026-10-03)

> 읽은 사람이 **남길 수 있게**(방명록 · 블록에 댓글), 방문 하나하나가 **어느 버전을 봤는지** 남게, 그리고 **남겼을 때 버전과 지금 버전이 다르면** 알 수 있게.

**버전** = `ez_items.version`. 에이전트가 고치든 사람이 글자를 고치든 블록을 옮기든 내용이 바뀌면 1 오른다(이미 그렇다). 화면에는 `v12` 처럼 쓴다. 남긴 것마다 그때 버전을 붙이고, **지금 버전과 다를 때만** 옆에 옅게 `v12` 가 보인다(같으면 아무것도 안 보인다 — 미니멀).

### 데이터

**`ez_visits` 방문** — 들어올 때마다 한 줄 (7-4 의 `ez_views` 는 기기 요약, 이것은 낱낱)
| 칸 | 규칙 |
|---|---|
| `id` `view_id` → `ez_views` on delete cascade | 어느 기기(사람)의 방문인지 |
| `version` | 들어왔을 때 보고서 버전 |
| `started_at` `last_at` `seconds` | 그 방문의 시작 · 마지막 핑 · 읽은 시간. 7-4 의 핑이 **현재 방문**에 더한다(`ez_views.seconds` 는 방문들의 합) |
- 기기당 200줄까지(넘으면 오래된 것부터). "현재 방문" = 그 기기의 마지막 방문이 30분 안에 살아 있으면 그것, 아니면 새 방문

**`ez_notes` 방명록 · 댓글** — 한 테이블, `block` 이 없으면 방명록
| 칸 | 규칙 |
|---|---|
| `id` `item_id` → `ez_items` on delete cascade | |
| `view_id` → `ez_views` (null 가능) | 쓴 사람. **주인이 쓴 것은 null** + `by_owner = true` |
| `by_owner` | 주인의 답글 |
| `body` | 1~1,000자. 텍스트로만 그린다 |
| `version` | 썼을 때 보고서 버전 |
| `block` `anchor` | 댓글만. `block` = 썼을 때 블록 번호, `anchor` = 그 블록의 글자 앞부분(소제목 또는 첫 60자). 버전이 바뀌어 블록이 움직였으면 `anchor` 로 다시 찾아 붙이고, 못 찾으면 "원래 n번째 블록" 으로 목록에만 |
| `created_at` `updated_at` `deleted_at` | 지우기는 soft |
- 보고서당 1,000줄까지. 한 기기는 10초에 하나

**함수 (anon)** — 7-4 와 같은 방식(열쇠 → 공유 켜진 살아 있는 보고서, 없으면 빈 결과)
| 함수 | |
|---|---|
| `ez_notes_list(token)` | 그 보고서의 방명록 · 댓글 전부(지운 것 빼고) + 쓴 사람 라벨(이름 또는 게스트 n) + 각각의 `version`. 주인 답글은 `by_owner` |
| `ez_note_write(token, device, body, block?, anchor?)` | 쓰기. 그 기기의 `ez_views` 줄이 있어야 한다(없으면 먼저 `ez_view_open`). `version` 은 함수가 지금 것을 적는다 |
| `ez_note_edit(token, device, id, body?)` / 지우기는 `body` 없이 | **같은 기기가 쓴 것만** |

주인은 RLS 아래 직접(읽기 · 답글 쓰기 · 아무 것이나 지우기). 지운 것은 주인에게도 안 보인다(휴지통 없음)

- **댓글 줄은 블록 아래에** 펼친다(데스크톱도). 1440 폭에서 종이 오른쪽 여백은 148px 뿐이라 옆에 글을 적을 자리가 없다. 댓글 수만 오른쇽 여백에 작은 숫자로, 폰과 2칸 행(사진 옆 글)은 블록 아래 숫자로. 댓글이 없는 블록은 데스크톱에서 블록에 올렸을 때만 `+` 가 비친다(키보드로도 닿게)
- `ez_notes.version` 은 **insert 트리거**가 `ez_items.version` 의 지금 값을 적는다 — 함수로 쓰든 주인이 RLS 로 직접 넣든 같은 길. 1,000줄 상한(지운 것 포함 — 저장 상한이다)도 같은 트리거가 본다. 넘으면 `[EZ_LIMIT]`, 10초 규칙은 `[EZ_RATE]` — 지우지 않고 거절한다(남의 글을 조용히 밀어내지 않는다)
- 주인의 select 정책에는 `deleted_at is null` 을 **넣지 않는다**. Postgres 는 where 가 있는 update 의 새 줄에도 select 정책을 적용해, 그 조건이 있으면 soft delete 자체가 거절된다. 지운 글은 화면 · MCP 가 `deleted_at is null` 로 걸러 읽는다(anon 함수는 SQL 안에서 뺀다)
- 주인은 열 권한으로 묶는다: insert 는 `item_id · by_owner · body · block · anchor` 만, update 는 `deleted_at` 만. 그래서 주인도 남의 글자를 못 고친다
- `ez_notes_list` 는 글마다 `guest_no` 를 같이 준다 — 공개 페이지가 `ez_view_open` 이 돌려준 자기 번호와 비교해 "내 글"(고치기 · 지우기)을 안다. 기기 열쇠는 남에게 안 나간다
- `ez_shared` 에 `version` 을 더했다(0014 에서 다시 만듦) — 공개 페이지도 글의 버전과 지금 버전을 비교해야 한다
- `view_id` 는 `on delete set null` — 기기 줄이 500줄 상한으로 지워져도 글은 남고 라벨만 "게스트" 가 된다
- 블록을 다시 찾는 순서는 같은 버전이면 그 번호 그대로, 다르면 anchor(원래 자리 먼저 → 앞에서부터) → 같은 번호(범위 안) → 못 찾음. anchor 는 소제목, 없으면 첫 글의 앞 60자(강조 표시 · 겹친 공백 뺌). 사진은 설명 또는 대체 글
- 주인 글의 이름은 공개 페이지 "주인", 주인 화면 "나". 공개 페이지에서는 적는 칸에 자리표시("남길 말" · "댓글")와 단추만 — 설명 문구 없음
- "이름 적기" 가 한 번 더 보이는 곳은 **블록 댓글 칸 옆**뿐. 방명록 칸 바로 아래가 이름 칸이라 거기에는 겹쳐 두지 않는다. 누르면 맨 아래 이름 칸을 열고 그리로 스크롤한다
- 키위 점의 기준 "마지막으로 창을 연 때" 는 기기의 `localStorage` (`ezwork.seen:<보고서 id>`). 보는 사람 칸은 그 뒤 **처음 온** 사람(first_at)만 센다 — 읽고 있을 때마다 점이 켜지지 않게. 창을 여는 순간 지금으로 바꾸고, 열려 있는 동안의 칸 점은 그 전 값 기준
- 공개 페이지는 글 목록을 열어 둔 동안 **30초마다** 다시 읽는다(핑 간격과 같다). 쓰기 · 고치기 · 지우기는 화면을 먼저 바꾸고 실패하면 되돌린다
- 확인 모드 표본은 방명록 2 · 주인 답글 1 · 댓글 3(하나는 v2 때 0번 블록에 쓴 것이 1번으로 옮겨진 것, 하나는 없어진 블록 → "원래 6번째 블록") · 방문 11줄. 보고서는 v3
- MCP `report_get` 의 `notes` 는 범위 없는 결과에만, 있을 때만 싣는다 — 라벨(주인 글은 "주인") · 그때 `version` · `block` · `anchor` · 글 · 쓴 때. id 는 싣지 않는다(쓰기 도구가 없다)

## 7-6. 댓글은 블록 옆에 · 셀 병합 (2026-10-04 피드백)

### 댓글 — 블록 옆 패널 (구글 문서 · 노션 방식)

7-5 에서 "데스크톱도 블록 아래" 로 갔던 것을 되돌린다. **넓은 화면에서는 댓글이 블록 오른쪽 옆에 패널로 펼쳐지고, 종이가 왼쪽으로 밀리면서 종이 + 패널 전체가 가운데 정렬**된다. 좁은 화면(종이 폭 760 미만 · 폰)은 지금처럼 블록 아래.

- 닫힌 상태: 댓글이 있는 블록의 오른쪽 여백에 작은 숫자(지금과 같다). 종이는 가운데
- 블록(또는 숫자)을 누르면: 그 블록의 댓글 줄이 **블록과 같은 높이**에서 오른쪽에 펼쳐진다. 패널 폭 340. 종이는 왼쪽으로 170(패널의 절반)만큼 밀려 "종이 + 패널" 이 가운데가 된다
- 모션(`docs/모션.md`): 종이는 `transform: translateX(-170px)`, 패널은 오른쪽에서 `translateX(16px) → 0` + 불투명도. 240ms, `--ease-out`. 폭을 애니메이션하지 않는다(레이아웃 흔들림 금지). reduced-motion 이면 즉시
- 한 번에 하나만 펼친다. 다른 블록을 누르면 패널이 그 블록 높이로 옮겨 간다(패널 안의 내용만 바뀌고, 세로 위치는 `transform` 으로). Esc · 빈 곳 누르기 · 같은 블록 다시 누르기 = 닫힘 → 종이가 가운데로 돌아온다
- 패널 안: 댓글 줄들(라벨 · 상대 시간 · 글 · 다른 버전이면 옅은 `v12`) + 적는 칸(공개 페이지는 자기 글 고치기 · 지우기, 주인은 답글 · 지우기). 패널이 블록보다 길면 패널만 아래로 자란다(종이는 그대로)
- 차례 레일(오른쪽 168px)과 겹치면 레일은 그 동안 숨긴다(펼친 동안만)
- 고치기 모드(손잡이 · 도구 줄)에서는 댓글 숫자 · 패널을 그리지 않는다(지금과 같다)
- 공개 페이지(`/s/…`)와 주인 화면 둘 다 같은 컴포넌트

### 방명록 — 주인은 읽기만

방명록은 **보는 사람이 남기는 것**이다. 주인 화면의 방명록 칸에는 적는 칸(답글)을 두지 않는다 — 목록 · 지우기만. 주인이 할 말이 있으면 블록 댓글에 답글로

### 표 — 셀 병합

에이전트가 표를 만들 때 칸을 가로 · 세로로 합칠 수 있다(사람이 손으로 합치는 UI 는 없다 — 구조는 에이전트 몫).

- 블록 어휘(3장 표에 더함): `table.merges?: [{r, c, rows, cols}]` — `r`·`c` 는 0부터(머리 행은 못 합친다 · `cols` 머리는 그대로), `rows`·`cols` ≥ 1 이고 둘 다 1 이면 거절. 범위가 표 밖이거나 서로 겹치면 거절(위치와 이유 반환: `blocks[2].merges[1]: 칸이 겹칩니다`)
- **덮이는 칸은 비워 둔다**(`""`). 비어 있지 않으면 거절 — "합쳐진 자리에 글이 있습니다: rows[3][2]". 그래야 사람이 글자를 고칠 때 덮인 칸을 건드릴 일이 없다
- 그리기: 시작 칸에 `rowSpan` · `colSpan`, 덮인 칸은 그리지 않는다. 좁은 화면의 행 카드(앞서 더한 것)에서는 세로 병합은 첫 행 카드에만 보이고, 가로 병합은 열 이름을 `a · b` 로 이어 붙인다
- Markdown 내보내기: GFM 표는 병합이 없으므로 시작 칸의 글을 덮인 자리마다 반복하지 않고 **빈 칸**으로 둔다(지금 저장 모양 그대로)
- 글자 고치기: 시작 칸만 고칠 수 있고 덮인 칸은 경로가 없다(`ez_edit_rule` 은 그대로 — 화면에 안 그리므로 칸이 없다)
- MCP: `report_create` · `report_edit` 도구 설명의 블록 어휘 요약에 `merges` 한 줄
- 공유 페이지 · 주인 화면 · 검색(`ez_search` 는 문자열 값만 보므로 영향 없음)

## 8. 원격 MCP (남이 연결할 때 — 나중)

지금은 로컬 stdio + service role 키라 **이 PC 에서 나만** 쓴다. 이 키는 절대 남에게 주지 않는다.
팀원·서비스로 열 때는 MCP 를 웹앱에 올려(`/api/mcp`, Streamable HTTP) 사람마다 자기 권한으로 들어오게 한다.

| 방식 | 사용자가 하는 것 | 붙는 곳 | 만드는 양 |
|---|---|---|---|
| **개인 토큰** (먼저) | 설정 '에이전트 연결' → 토큰 만들기(한 번만 보임) → `claude mcp add --transport http ezwork <주소> --header "Authorization: Bearer <토큰>"` | Claude Code | 작음 |
| **OAuth** (나중) | 주소만 넣음 → 브라우저에서 EZ.WORK 로그인·허용 → 자동 발급 | Claude Code · claude.ai 커넥터 · 폰 | 큼. Supabase 가 OAuth 서버를 지원하는지 확인 필요 |

- 토큰: DB 에는 해시만. 이름·범위(읽기/쓰기)·만료·마지막 사용·폐기
- 서버: 토큰 → 사용자 → 그 사람 것만. 지금 MCP 가 모든 쿼리에 owner 조건을 거는 구조라 그대로 이어진다
- 도구 로직(`mcp/drawer.ts`)은 연결 방식과 분리돼 있어, 연결 층과 토큰 확인만 더하면 된다

## 8-1. 사진 블록 (다음 단계 — 방향만 정함, 2026-09-30)

- **배치**: 사진이 글과 같은 행에 선다(노션처럼 위아래로만 쌓지 않음). 처음엔 한글 '어울림'(글이 사진 옆으로 흐름)이었으나 한 행에 객체가 3개 서는 문제로 **2칸 행**으로 바꿈 → 7-3장
- 에디터 없음 원칙 그대로 — **에이전트가 블록 속성으로 배치를 적는다**: `place: left | right | full`, `size: 1/3 | 1/2 | 2/3`. 화면은 그리기만
- 읽는 행 폭 약 1,280px 전제. 폰(좁은 폭)에서는 옆 배치를 풀고 위아래로 쌓는다
- 저장: DB(`blocks`)에는 위치·설명·크기만. 파일은 Supabase Storage **비공개 버킷**, 볼 때만 잠깐 유효한 주소
  - **원본은 서버에 올리지 않는다.** 에이전트(MCP)가 올리기 전에 줄여서 **줄인 것 한 장만** 올린다: 긴 변 1,280px, WebP. 같은 사진은 내용 해시로 한 번만
  - **서버도 막는다** (에이전트 실수 대비): 버킷에 허용 형식 `image/webp` 만, 파일 크기 상한(약 500KB). 이걸 넘는 건 저장소가 거절
  - 크게 보기도 1,280px 까지(늘려서 흐리게 보이지 않게 원래 크기로)
  - 내 PC 의 원래 파일은 건드리지 않는다(지우는 건 사람 몫)
  - 추정: 장당 약 120~300KB → 1GB 에 약 3,500~8,000장
  - 보고서 영구 삭제 때 사진도 같이 삭제(주인 없는 파일 방지)
- **출처 필수**: 사진마다 어디서 왔는지 단다. 원본을 안 올리는 대신 **출처로 원본에 갈 수 있게**
  - 웹에서 가져온 사진 → `ref`: 보고서 출처 블록 번호(근거의 인용 번호와 같은 방식, 범위 밖 번호 금지)
  - 직접 만든 사진 → `credit`: 짧은 글(예: `직접 캡처`, `직접 촬영`)
  - **온라인 출처가 없으면 내 PC 원본 위치** → `local_path`: MCP 가 올릴 때 읽은 파일 경로를 그대로 적는다(예: `C:/Users/PC/Pictures/캡처/2026-09-30.png`). 사람이 따로 적을 필요 없음
    - 화면: `원본 · 내 PC · <경로>` + **경로 복사** 버튼. 브라우저는 보안상 PC 파일을 직접 못 여니 복사해서 탐색기에 붙여 넣는 방식
    - "올린 당시 위치"다. 파일을 옮기거나 지우면 안 맞을 수 있다
    - **공유 페이지에는 안 보인다** — 경로에 사용자 이름·폴더 구조가 드러나므로. 공유 페이지에는 `직접 만든 사진` 정도만
  - `ref` · `credit` · `local_path` 중 하나는 반드시 있어야 블록 검사 통과
  - 화면: 사진 아래 작은 한 줄 `출처 [n] 제목 · 도메인` — 누르면 원본 페이지로(새 탭)
  - 공유 링크로 공개할 때 남의 사진은 출처를 달아도 사용 허락이 되는 것은 아니다 — 공개 보고서에는 주의
- 올리는 쪽: 주로 MCP(`report_create`/`report_edit` 에 로컬 사진 경로 → 줄이고 올리고 블록에 넣음)
- 미정: 사진 배치(좌·우·크기)를 **손으로** 바꾸게 할지 — '형식은 안 바뀜' 원칙과의 경계

**구현하며 정한 규칙** (5단계, 마이그레이션 0004)
- 블록: `{type:"image", src, w, h, alt, caption?, place, size?, ref?, credit?, local_path?}`. `size` 가 없으면 1/2 로 그린다(full 이면 무시). 사람은 `alt`·`caption` 글자만 고친다. 블록 어휘 버전은 1 그대로(종류만 더함)
- **출처 필수는 입력 검사(`validateBlocks`)에서만** 본다. 그리기용 스키마는 출처 없이도 통과 — 공유 페이지는 `local_path` 를 뺀 블록을 받으므로, 막으면 사진이 "볼 수 없는 블록"이 된다
- MCP 는 `file`(PC 절대 경로만, 상대 경로는 거절)을 받으면 `ref`·`credit` 이 있어도 **`local_path` 를 늘 채운다**. `src` 를 직접 주면 이 서랍 주인 폴더에 실제로 있는 사진만 받는다
- 사진 아래 출처 줄은 하나: `ref` → `credit` → `local_path` 순. 공유 페이지에서 `local_path` 만 있던 사진은 **출처 줄 없음**(PC 파일이 직접 만든 것이라는 보장이 없어 '직접 만든 사진'이라 적지 않는다)
- 사진의 `h` 는 높이라 차례(레일)에서 빠진다
- 찾기(`ez_search`)는 `src`·`place`·`size`·`local_path` 값을 사용자 글자로 보지 않는다(`type`·`tag`·`url` 과 같이)
- ~~옆 사진이 있는 보고서는 글 폭 상한(72ch)을 풀고 읽는 행(1,280px)을 상한으로~~ → 7-3장(본문 920px, 2칸 행)으로 바뀜
- 공유 페이지의 사진 읽기(anon)는 공유 켜진 살아 있는 보고서가 그 경로를 쓰고, 경로의 첫 폴더가 그 보고서 주인일 때만
- 주인 없는 사진(살아 있든 휴지통이든 어느 보고서도 안 씀 + 올린 지 14일 넘음)은 MCP 서버 시작 때와 `npm run purge-images` 로 Storage API 가 지운다(SQL 로는 못 지움)

**자르기 · 가장자리** (2026-10-01)
- 입력 `crop: {x, y, w, h}`(원본 픽셀, 정수, 방향 EXIF 를 반영한 모양 기준) — MCP 가 먼저 잘라낸 뒤 위 규칙(1280·확대 금지·WebP·500KB)을 적용한다. 사진 밖이면 거절. `crop` 은 저장하지 않고 잘린 결과만 올라간다. `file` 없이 주면 거절(이미 올린 사진은 못 자름). 화면 캡처는 통째로 넣지 않고 보여줄 부분만
- `edge: light | dark` — MCP 가 올리기 직전 결과 사진의 가장자리 띠(각 변 4%)의 평균 상대 휘도를 재서 채운다: **0.8 이상 light, 0.03 이하 dark**, 그 사이는 없음(투명이 절반 넘으면 없음). 에이전트가 준 값은 `file` 이 있으면 버린다. 사람은 못 고친다
- 화면: 라이트 테마 + `light`, 다크 테마 + `dark` 일 때만 사진에 포인트색 2px 테두리(바탕에 녹아 경계가 안 보이는 사진). 공유 페이지도 같다
- 찾기(`ez_search`, 0005)는 `edge` 값도 사용자 글자가 아니라서 뺀다
