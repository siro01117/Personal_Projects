# 보고서 서랍 — 설계서 v1

> EZ.WORK 첫 삽. 에이전트(Claude Code)가 MCP 로 서칭 보고서를 **블록으로 조립**해 넣고, 사람은 **윈도우 탐색기처럼** 폴더로 정리하고 읽는다.
> 2026-09-30 작성. 로컬에서 만들고, 일정까지 끝나면 배포.

## 0. 정해진 것 (노션 답변·목업 피드백)

- 이름 EZ.WORK · 라칸 재사용 안 함(가져갈 것은 일정 규칙·데이터뿐, 이 단계와 무관)
- 보고서 = **블록 조립만**. HTML 통째 올리기 없음
- 보고서 종류 = 서칭 보고서 3종: 작업 방식 조사 · 데이터 조사 · 레퍼런스 조사
- 사람은 **글자만** 고친다. 블록 구조(종류·개수·순서·표 칸 수)는 안 바뀐다
- 로그인 없이 **읽기 전용 공유 링크**
- MCP 는 **내 PC 에서 Claude Code 가 실행하는 로컬 방식**. 별도 서버 없음
- 화면: 미니멀 1차 · 키위 포인트 · 데스크톱 폭 전체 · 가운데 큰 아이콘 · 탐색기(선택/열기/우클릭/끌어 옮기기/되돌리기)

## 1. 구성

```
ez-work/
  lib/        블록 스키마·이름 규칙·경로 — 웹과 MCP 가 같이 씀 (한 곳에서만 정의)
  app/        Next.js 웹 (로그인 · 홈 · 탐색기 · 보고서 · 공유 페이지)
  mcp/        로컬 MCP 서버 (stdio) — Claude Code 가 실행
  db/         SQL 마이그레이션 + PGlite 로 도는 DB 테스트
  docs/       이 문서
```

- 데이터: RA-KAN Supabase 프로젝트 안, **`ez_` 로 시작하는 테이블만**. 일정(`kv`)은 손대지 않음
  - Supabase 는 새 스키마를 쓰려면 대시보드에서 따로 열어야 해서, 같은 효과를 접두사로 낸다. 나중에 싹 밀 때 `ez_*` 가 아닌 것을 지우면 된다
- 로그인: RA-KAN 의 Supabase Auth 계정 그대로
- 테스트 DB: **PGlite**(브라우저·Node 에서 도는 Postgres). 도커 없이 트리거·제약을 진짜 Postgres 로 시험한다

## 2. 데이터 — 테이블 하나 `ez_items`

폴더와 보고서를 **한 테이블**에 둔다. 윈도우처럼 한 폴더 안에서 폴더·파일 이름이 서로 겹치면 안 되는데, 테이블이 하나여야 그걸 인덱스 하나로 막을 수 있다.

| 열 | 뜻 |
|---|---|
| `id` uuid | |
| `owner` uuid | auth 사용자 |
| `parent_id` uuid? | 담긴 폴더. 없으면 서랍 맨 위 |
| `kind` | `folder` / `report` |
| `name` | 폴더 이름 = 보고서 제목 |
| `report_kind` | `method` / `data` / `reference` (보고서만) |
| `blocks` jsonb | 블록 배열 (보고서만) |
| `schema_version` int | 블록 어휘 버전. 지금 1 |
| `agent` text | 쓴 에이전트 이름 (`Claude Code`) |
| `version` int | 고칠 때마다 +1. 동시 수정 충돌 감지용 |
| `agent_updated_at` | 에이전트가 마지막으로 쓴 시각 |
| `read_at` | 내가 마지막으로 연 시각. `agent_updated_at > read_at` 이면 안 읽음 |
| `share_token` text? | 공유 링크 열쇠. 없으면 비공개 |
| `deleted_at`, `deleted_batch` | 지운 것(휴지통). 같이 지운 묶음 id |
| `created_at`, `updated_at` | |

DB 가 막는 것 (웹·MCP 어느 쪽 실수든 여기서 걸린다):
- 같은 폴더 안 같은 이름 — 대소문자·앞뒤 공백 무시, 지운 것은 제외 (부분 유일 인덱스)
- 이름: 앞뒤 공백 제거 후 1~100자, `/` 금지(MCP 경로 구분자), 줄바꿈·제어문자 금지
- `parent_id` 는 **살아 있는 폴더**만
- 자기 자신·자기 자손 안으로 옮기기 금지 (순환)
- 폴더 깊이 최대 8단
- 보고서만 `blocks` 를 가짐, 폴더는 `blocks` 없음
- `blocks` 크기 상한 600KB
- 다른 사람 것은 못 봄·못 고침 (RLS: `owner = auth.uid()`)

## 3. 블록 어휘 v1

서칭 보고서의 뼈대에서 뽑았다. `lib/blocks.ts` 한 곳에서 zod 로 정의하고, MCP 는 넣기 전에 검사한다.

| 종류 | 필드 | 규칙 |
|---|---|---|
| `verdict` 판정 | `v` 한 줄, `w?` 풀이 | 보고서당 최대 1개 |
| `text` 문단 | `h?`, `body` | body ≤ 4,000자 |
| `list` 목록 | `h`, `items[]` | 1~30개, 각 ≤ 600자 |
| `table` 표 | `h`, `cols[]`, `rows[][]` | 열 2~8, 행 1~60, **모든 행의 칸 수 = 열 수**, 칸 ≤ 300자 |
| `claims` 근거 | `h`, `items[{tag,text,refs[]}]` | tag = `fact`(사실) / `guess`(추정). refs 는 출처 번호(1부터) — **출처 범위 밖 번호 금지** |
| `sources` 출처 | `h`, `items[{title,url}]` | 보고서당 최대 1개, 1~100개, **url 은 http/https 만** |

- 보고서당 블록 1~200개
- 검사 실패 시 에이전트가 고칠 수 있게 **위치와 이유**를 돌려준다
  예: `blocks[2].rows[3]: 칸이 3개인데 열은 4개입니다`
- 화면은 **모르는 블록 종류를 만나도 깨지지 않는다** — "이 블록은 아직 볼 수 없습니다" 자리표시
- 글자는 전부 텍스트로만 그린다(HTML 해석 안 함) → 보고서 안 문자열로 스크립트가 못 들어온다

### 사람이 고칠 수 있는 칸

문자열 칸 중 아래만. 그 외(`type`, `tag`, `url`, `refs`, 칸 수)는 손으로 안 바뀜.

`verdict.v/w` · `text.h/body` · `list.h/items[i]` · `table.h/cols[i]/rows[i][j]` · `claims.h/items[i].text` · `sources.h/items[i].title` · 보고서 제목

- DB 함수 `ez_edit_text(id, base_version, path, value)` 가 **그 자리가 원래 문자열인지, 허용된 칸인지** 확인하고 바꾼다
- 빈 값 금지, 길이 상한은 블록 규칙과 같음

## 4. MCP 도구 (6개)

도구 설명은 매번 Claude Code 컨텍스트에 실리므로 **개수를 줄였다**. 경로는 `/` 로 시작: `/`(맨 위), `/EZ.WORK 준비/APPTIVE`.

| 도구 | 하는 일 | 엣지 |
|---|---|---|
| `drawer_list(path?, query?)` | 폴더 안 목록(폴더 먼저, 각각 이름순 — `localeCompare('ko')` 라 한글이 영문보다 앞). `query` 를 주면 제목·본문 찾기: `path` 를 같이 주면 그 폴더 아래(자손 포함)로 좁힘, 최대 20개, 각 결과에 `match`(`name`/`body`)와 본문 맞은 자리 앞뒤 약 40자 `snippet`. DB 함수 `ez_search` 가 보고서 안 사용자 글자(문자열 값, `type`·`tag`·`url` 제외)만 찾는다 | 없는 경로 → 오류 + 가장 가까운 폴더 제안 |
| `drawer_mkdir(path)` | 폴더 만들기, 중간 폴더도 | 이미 있으면 그대로 성공. 중간에 실패하면(깊이 등) 이번에 만든 폴더만 되돌림 |
| `drawer_update(target, move_to?, rename?, delete?)` | 옮기기 · 이름 바꾸기 · 휴지통으로 | 옮기기: 순환·삭제된 폴더 금지, 이름 겹치면 `(2)`. 이름 바꾸기: 겹치면 거절(사람이 정한 이름이라 자동 변경 안 함) |
| `report_create(title, kind, folder, blocks)` | 보고서 넣기. **도구 설명에 블록 어휘 요약을 담는다** | 검사 실패 → 위치·이유 목록. 제목 겹치면 `(2)` 붙이고 알려줌 |
| `report_get(id, from?, to?)` | 보고서 읽기, **블록 범위만 가능** | 범위 없으면 차례 + 판정만(통째로 먹이지 않음) |
| `report_edit(id, base_version, ops[])` | 블록 넣기·바꾸기·빼기 | `base_version` 이 낡았으면 충돌 + 현재 버전 반환 |

- `target` 은 id 또는 경로
- 인증: `.env.local` 의 service role 키 + 내 사용자 id. 이 PC 에서만 돈다
- 에이전트가 쓰면 `agent_updated_at` 갱신 → 서랍에 안 읽음 점

## 5. 화면 동작

**탐색기**
- 폴더 먼저, 그다음 보고서. 각각 이름순(한국어 정렬 — 한글이 영문보다 앞)
- 한 번 누르면 선택 · 두 번 누르면 열기 · 터치는 한 번에 열기
- 우클릭 / 길게 누르기 메뉴: 열기 · 이름 바꾸기 · 옮기기 · 공유 · 삭제. 빈 곳: 새 폴더
  - 옮기기 = 옮길 폴더 목록(목업 방식). 공유 = 그 보고서를 열고 공유 창을 띄움(폴더는 공유 없음)
- 끌어 놓기: 폴더 위, 또는 위쪽 경로 위. 자기 자신·현재 폴더 위는 무동작
- 옮긴 뒤 알림에도 "되돌리기"(원래 폴더로 다시 옮김, 목업대로)
- 새 폴더: 빈 이름 `새 폴더`, 겹치면 `새 폴더 (2)`, 만들자마자 이름 입력
- 키보드: 화살표 · Enter · F2 · Delete · Backspace(상위) · Esc(취소)
- 경로가 길면 가운데를 `…` 로 접음
- 빈 폴더: "빈 폴더" 한 줄

**이름 바꾸기**
- Enter 저장 · Esc 취소 · 다른 곳 누르면 저장
- **한글 조합 중 Enter 는 무시**(`isComposing`) — 안 그러면 마지막 글자가 잘리거나 두 번 저장됨
- 겹치는 이름 → 입력 유지하고 "같은 이름이 이미 있습니다"
- 앞뒤 공백 자동 제거, 빈 이름이면 취소

**삭제·되돌리기**
- 삭제는 휴지통으로(바로 사라지지 않음). 폴더를 지우면 안의 것도 같은 묶음으로
- 알림의 "되돌리기" = 묶음째 복원
- 복원할 자리의 폴더가 그 사이 지워졌으면 **서랍 맨 위로** 복원하고 알림
- 복원할 이름이 그 사이 생긴 것과 겹치면 `(2)` 붙여 복원
- 휴지통 화면·30일 뒤 영구 삭제는 **다음 단계**

**보고서**
- 블록을 그린다. 오른쪽 레일 = 차례(넓을 때만)
- 연필 = 글자 고치기 모드. 블록 경계가 보이고 글자 칸만 고칠 수 있음
- 저장은 칸에서 벗어날 때. 실패하면 원래 글자로 되돌리고 알림
- **동시 수정**: 그 사이 다른 곳(에이전트·다른 창)에서 고쳤으면(버전 불일치) "방금 다른 곳에서 이 보고서를 고쳤습니다" + "새로 불러오기". DB 는 누가 고쳤는지 알려주지 않는다
- 열면 읽음 처리

**공유**
- 공유 켜기 → 링크 생성(추측 불가 22자). 끄기 → 링크 무효. 다시 켜면 **새 링크**(옛 링크 계속 무효)
- 공유 페이지 `/s/[열쇠]`: 로그인 없이, 읽기만, 검색엔진 차단(noindex)
- 지운 보고서·꺼진 링크 → "없는 링크입니다" (있었는지 여부를 드러내지 않음)
- DB 함수 `ez_shared(token)` 로만 읽음. 웹에 service role 키를 두지 않는다

**공통**
- 저장은 화면을 먼저 바꾸고(낙관적), 실패하면 되돌리고 알림
- 로그인 풀림 → 로그인 화면, 돌아오면 있던 자리로
- 모바일: 탐색기 3열, 끌어 놓기 대신 메뉴의 "옮기기"

## 6. 시험

| 층 | 무엇 | 도구 |
|---|---|---|
| lib | 블록 검사(정상·경계·오류 문구) · 이름 규칙 · 경로 해석 · `(2)` 붙이기 | vitest |
| DB | 이름 겹침 · 순환 · 깊이 · 죽은 부모 · RLS · `ez_edit_text` 경로 가드 · 복원 충돌 · 공유 | PGlite + vitest |
| MCP | 6개 도구 입력 검사 · 오류 문구 · 부분 읽기 · 찾기 · 되돌리기 | PGlite 위 진짜 DB 규칙 + vitest (마이그레이션을 그대로 돌리고 service_role 로 실행) |
| 웹 | 위 5장 동작을 손으로 한 바퀴 + 한글 이름 바꾸기 | 브라우저 |

## 7. 순서

1. **lib + DB** — 블록 스키마, 이름 규칙, 마이그레이션, 테스트
2. **MCP** — 에이전트가 진짜 보고서를 넣을 수 있게 (넣을 데이터가 먼저 있어야 화면을 제대로 본다)
3. **웹** — 로그인 · 홈 · 탐색기 · 보고서 · 글자 고치기 · 공유
4. **엣지케이스 점검** — 5장 목록 한 바퀴, 깨진 것 고치기

## 8. 원격 MCP (남이 연결할 때 — 나중)

지금은 로컬 stdio + service role 키라 **이 PC 에서 나만** 쓴다. 이 키는 절대 남에게 주지 않는다.
팀원·서비스로 열 때는 MCP 를 웹앱에 올려(`/api/mcp`, Streamable HTTP) 사람마다 자기 권한으로 들어오게 한다.

| 방식 | 사용자가 하는 것 | 붙는 곳 | 만드는 양 |
|---|---|---|---|
| **개인 토큰** (먼저) | 설정 '에이전트 연결' → 토큰 만들기(한 번만 보임) → `claude mcp add --transport http ezwork <주소> --header "Authorization: Bearer <토큰>"` | Claude Code | 작음 |
| **OAuth** (나중) | 주소만 넣음 → 브라우저에서 EZ.WORK 로그인·허용 → 자동 발급 | Claude Code · claude.ai 커넥터 · 폰 | 큼. Supabase 가 OAuth 서버를 지원하는지 확인 필요 |

- 토큰: DB 에는 해시만. 이름·범위(읽기/쓰기)·만료·마지막 사용·폐기
- 서버: 토큰 → 사용자 → 그 사람 것만. 지금 MCP 가 모든 쿼리에 owner 조건을 거는 구조라 그대로 이어진다
- 도구 로직(`mcp/drawer.ts`)은 연결 방식과 분리돼 있어, 연결 층과 토큰 확인만 더하면 된다
