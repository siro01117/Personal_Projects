# 회원 · 추가 모듈 — 설계서 v1 (2026-10-04)

관리자(한결)가 **아이디 · 비밀번호 계정을 만들어 주고**, 그 사람이 로그인해 EZ.WORK 를 쓴다. 기본 모듈은 다 쓰고, 관리자가 열어 준 **추가 모듈**은 사이드바 아래 선택창에서 골라 켠다. 데이터는 **각자 따로**(지금 RLS 그대로 — 회원마다 자기 보고서 · 일정 · 할 일 · 모임).

## 0. 정해진 것 (2026-10-04)

- 로그인 전에는 로그인 화면이 막는다(지금과 같다). 가입은 없다 — 계정은 관리자만 만든다
- 로그인하면 **기본 모듈 네 개**(보고서 서랍 · 일정 · 플래너 · 모임)는 모두 쓴다
- 사이드바 맨 아래 **"추가 모듈"** — 누르면 선택창이 뜨고, 관리자가 그 회원에게 열어 준 모듈만 보인다. 켜면 사이드바 · 홈에 생긴다. 배너가 아니라 선택창이다
- 계정 만들기 · 비밀번호 · 권한은 **웹 관리 화면**에서. service_role 키는 Vercel 서버 환경변수(`EZ_SUPABASE_SERVICE_ROLE_KEY`, production · preview, sensitive)에만 — 브라우저에 절대 나가지 않는다. 관리자 id 는 `EZ_OWNER_ID`
- 안 만드는 모듈: 학습기 · 학습 노트(보고서 서랍으로 대신) · IA · 유저플로우 · 시작 질문지(나중에 프로젝트 하위로)

## 1. 역할

| | 관리자 | 회원 |
|---|---|---|
| 누구 | `EZ_OWNER_ID`(한결). DB 의 `ez_admins` 한 줄 | 관리자가 만든 Supabase Auth 사용자 + `ez_members` 한 줄 |
| 로그인 | 이메일 + 비밀번호(지금 그대로) | **아이디** + 비밀번호. 아이디는 안에서 `<아이디>@members.ra-kan.cloud` 로 바뀌어 Supabase 이메일이 된다(실제 메일은 안 간다 — `email_confirm: true` 로 만든다) |
| 기본 모듈 | 다 | 다 |
| 추가 모듈 | 모두 보임 | 관리자가 허용한 것만 선택창에 보임 |
| 관리 화면 `/admin` | 보임 | 없음(주소로 들어가도 "권한이 없습니다") |
| MCP(로컬 에이전트) | 관리자 데이터만(지금 그대로) | 없음 |

- 로그인했는데 관리자도 회원도 아니면(옛 계정 등) "이 계정은 쓸 수 없습니다" + 로그아웃
- 회원이 `active = false` 면 로그인은 되지만 같은 문구 + 로그아웃(관리자가 끈 것)

## 2. 데이터

### `ez_admins`
| 칸 | |
|---|---|
| `user_id` pk | 마이그레이션이 `EZ_OWNER_ID` 값을 한 줄 넣는다(`00263c79-cc44-4b7a-a846-ab9d43f4e718`) |
| `picked` text[] | 관리자가 켠 추가 모듈(관리자는 `ez_members` 줄이 없어서 여기에 둔다) |

### `ez_members` 회원
| 칸 | 규칙 |
|---|---|
| `user_id` pk → `auth.users` on delete cascade | |
| `login_id` | 영문 소문자 · 숫자 · `._-`, 3~20자, 유일(소문자 비교) |
| `name` | 1~20자 |
| `active` | 기본 true |
| `allowed` text[] | 관리자가 열어 준 추가 모듈 키들 |
| `picked` text[] | 회원이 켠 것(`allowed` 밖의 키는 화면이 무시) |
| `created_at` `updated_at` | |

### `ez_modules` 추가 모듈 (관리자가 등록)
| 칸 | 규칙 |
|---|---|
| `key` pk | 영문 소문자 · 숫자 · `-`, 2~30자 |
| `name` | 1~20자 |
| `kind` | `builtin`(앱 안의 경로 — 나중에 프로젝트 등) · `link`(바깥 주소 https 만, 새 탭) |
| `href` | builtin 은 `/` 로 시작하는 경로, link 는 `https://…` |
| `sort` | 정렬 |
| `created_at` | |

- 지금은 `link` 만 실제로 쓰인다(옛 라칸의 학습 페이지처럼 바깥에 있는 것을 걸어 두는 용도). `builtin` 은 구멍

### RLS · 권한
- `ez_is_admin()` = `exists(select 1 from ez_admins where user_id = auth.uid())`(security definer, stable)
- `ez_admins`: 아무도 직접 못 읽는다(함수로만)
- `ez_members`: 회원은 **자기 줄 select** + `picked` 열만 update. 관리자는 select · update(`name` · `active` · `allowed`). insert · delete 는 서버 라우트(service_role)만 — Auth 사용자와 같이 만들고 지워야 해서
- `ez_modules`: authenticated select, 관리자만 insert · update · delete
- 함수 `ez_me()` → `{role: 'admin' | 'member' | 'none', name, active, allowed, picked, modules}` 한 번에(첫 그림까지 왕복 1번 원칙). `modules` 는 그 사람에게 보이는 모듈 줄(관리자 전부 · 회원은 허용된 것 · 꺼진 회원은 없음, sort 순) — 사이드바가 이름 · 주소를 따로 읽지 않게
- 함수 `ez_set_picked(text[])` — 켠 것 저장. 회원은 자기 `ez_members.picked`, 관리자는 `ez_admins.picked`. 선택창은 이것만 부른다
- 모듈을 지우면 트리거가 모든 `allowed` · `picked` 에서 그 키를 뺀다
- 고치는 칸을 가르는 것은 트리거 `ez_members_guard`(열 권한은 역할 단위라 회원 · 관리자를 못 가른다): 회원은 `picked` 만, 관리자는 `name` · `active` · `allowed` 만. 어기면 `[EZ_FORBIDDEN]`

## 3. 서버 라우트 (`app/api/admin/…`, Node 런타임)

service_role 로 Supabase 를 만지는 곳은 여기뿐이다. 모든 요청은 **헤더의 세션 토큰**(`Authorization: Bearer <access_token>`)으로 부른 사람을 확인하고 `ez_admins` 에 있는지 본다. 아니면 403.

| 라우트 | 하는 일 |
|---|---|
| `GET /api/admin/members` | 회원 목록(`ez_members` + 마지막 로그인 시각 `auth.users.last_sign_in_at`) |
| `POST /api/admin/members` `{login_id, password, name, allowed}` | Auth 사용자 만들기(`auth.admin.createUser`, `email_confirm: true`) + `ez_members` 줄. 아이디 겹침 → 409 "이미 있는 아이디입니다" |
| `PATCH /api/admin/members/[id]` `{password?, name?, active?, allowed?}` | 비밀번호 다시 정하기(`auth.admin.updateUserById`) · 이름 · 끄기/켜기 · 허용 모듈 |
| `DELETE /api/admin/members/[id]` | Auth 사용자 지우기(cascade 로 `ez_members` 도). **그 회원의 데이터(`ez_items` 등)는 남는다** — 주인이 없는 행이 되므로 1차에서는 지우지 않고 보고서에 적어 둔다 |

- 비밀번호 규칙: 8자 이상(72바이트까지 — Auth 상한). 관리자가 정해 주고 회원에게 전달한다(회원이 스스로 바꾸는 화면은 1차에 없음)
- 환경변수 없으면(로컬에서 `.env.local` 의 같은 이름을 쓴다) 500 과 한국어 문구
- 호출자 확인: `auth.getUser(토큰)` → 그 id 가 `ez_admins` 에 있어야 한다. 토큰 없음 · 틀림 · 관리자 아님 모두 403. 실패 몸통은 `{code: 'EZ_…', message}`
- `allowed` 는 `ez_modules` 에 있는 키만(없으면 400 "없는 모듈입니다"). PATCH · DELETE 의 대상은 `ez_members` 에 있는 사람만(관리자 자신 · 남의 Auth 계정은 404)
- 회원 줄 넣기가 실패하면 방금 만든 Auth 사용자를 지운다(반쪽 계정을 남기지 않는다)
- 몸통은 `app/api/admin/members/handlers.ts`(클라이언트를 넣어 시험), service_role 클라이언트는 `client.ts` 에만

## 4. 화면

### 로그인 (`/login`)
- 칸 이름을 "이메일" → **"아이디 또는 이메일"**. `@` 가 없으면 `<아이디>@members.ra-kan.cloud` 로 바꿔 보낸다
- 틀리면 지금 문구 그대로

### 사이드바 · 홈 (`Shell` · `HomeView`)
- 기본 모듈 네 개는 그대로. 그 아래 회원이 켠 추가 모듈(`picked ∩ allowed`, `ez_modules.sort` 순). `link` 는 새 탭
- 맨 아래(휴지통 위): **추가 모듈** 단추 → 시트: 허용된 모듈마다 이름 + 켜기/끄기(끝냄 체크처럼 바로 저장, 낙관적). 허용된 것이 하나도 없으면 "아직 열린 모듈이 없습니다" 한 줄
- 관리자에게는 그 아래 **회원**(`/admin`) 한 줄 더
- 폰(사이드바 없음): 홈 타일에 켠 추가 모듈도 타일로. 홈 맨 아래에 "추가 모듈" 단추
- 홈은 데스크톱에서도 사이드바가 없으므로 켠 모듈 타일 · 맨 아래 "추가 모듈" 단추(관리자는 "회원" 단추도)를 모든 폭에서 보인다. 선택창은 데스크톱이면 단추 옆 작은 창, 폰이면 아래 시트
- `builtin` 모듈은 앱 안 링크(같은 탭), `link` 는 새 탭

### 관리 (`/admin`, 관리자만)
- **회원** 표: 아이디 · 이름 · 마지막 로그인 · 활성화(켬/끔은 누르면 바로 — 끔이면 로그인해도 "이 계정은 쓸 수 없습니다") · 허용 모듈(체크들, 바로 저장). 행을 누르면 시트: 이름 고치기 · 비밀번호 다시 정하기 · 지우기(확인 한 번)
- **회원 추가**: 아이디 · 비밀번호 · 이름 · 허용 모듈 → 만들기. 만든 뒤 아이디 · 비밀번호를 한 번 보여 준다(복사 단추) — 전달용
- **추가 모듈** 표: 키 · 이름 · 주소 · 지우기. 추가: 이름 · 주소(https) → 키는 이름에서 자동(영문 · 숫자 아니면 `m-` + 6자 무작위)
- 미니멀: 설명 문구 없음, 숫자 · 활성화는 글자 하나로

### 공통
- 로그인 뒤 `ez_me()` 를 한 번 읽어 `AppContext` 에 둔다(캐시 규칙은 다른 모듈과 같다). `none` · 꺼진 회원은 "이 계정은 쓸 수 없습니다" 화면 + 로그아웃 단추
- 첫 그림은 `ez_me` 를 기다리지 않는다(담아 둔 것이 없으면 추가 모듈 없이 먼저 그린다). 그래서 쓸 수 없는 계정은 처음 한 번 잠깐 앱이 보였다가 막힌다 — 데이터는 RLS 로 자기 것뿐이라 그대로 둔다. `ez_me` 를 못 읽으면(로그인 풀림 말고) 알리지 않고 추가 모듈 없이 둔다
- 공유 페이지(`/s/…`) · 모임 공개 페이지(`/m/…`)는 그대로(로그인 없음)

## 5. 시험
- DB(PGlite): 회원은 자기 줄만 · `picked` 만 고침, `allowed` 는 못 고침, 관리자는 전부, `ez_me()` 세 경우, `ez_modules` 쓰기는 관리자만, 키 · 아이디 규칙
- 라우트: 토큰 없음 403 · 회원 토큰 403 · 관리자 생성 → 목록 → 비번 변경 → 끄기 → 삭제(Supabase 클라이언트를 가짜로 바꿔 단위 시험)
- 화면: 아이디 → 이메일 변환, 사이드바에 켠 모듈만, 선택창 토글, 관리 표

## 6. 뺀 것
가입 · 비밀번호 찾기 · 회원 스스로 비밀번호 바꾸기 · 데이터 공유(팀) · 회원 삭제 때 데이터 삭제 · 초대 링크 · 로그인 기록
