# 일정 — 설계서 v1

> 2026-10-01. EZ.WORK 두 번째 모듈. 이게 끝나면 배포한다(라칸을 끌 수 있는 조건).
> 원칙은 보고서 서랍과 같다. 규칙은 한 곳(`lib`·DB), 미니멀 1차, 에이전트는 MCP 로.
> v0(2026-09-30) 에서 바뀐 것: 라칸 동작을 코드 근거로 다시 확인했고, 라칸이 못 하던 것을 고칠 목록(1장)을 더했다. MCP 도구는 6개에서 4개로 줄였다.

## 0. 정해진 것

- **핵심 두 가지**: 이번 주 시간표, 그리고 동선·외출 준비·식사 자동 계산. 라칸에서 매일 실제로 쓰는 것이다
- **빠짐**: 오늘 탭, 개요 탭, 할 일 끼워넣기·추천, 하루 부담 점수, 특별한 약속 목록
- **에이전트**: 읽기·쓰기 모두 (MCP)
- **구글 캘린더**: 연동 안 함. EZ.WORK 가 원본
- **바깥 일정**(스큐 근무·대학 시간표·동아리): 내장 연동을 만들지 않는다. **들어올 구멍만** 만들고 연동은 각자 에이전트가 한다
- **폰에서도 많이 고친다** → 폰 화면을 따로 설계한다
- 라칸에서 가져올 것은 **규칙(동작)과 데이터**. 코드는 가져오지 않는다

레퍼런스: **Google Calendar 주간 보기**. 격자, 끌어 옮기기·늘리기, 반복 일정 '이번만 / 이후 모두', 종일 줄.

목업: `docs/mockup/schedule-v1.html` (데스크톱 주간 · 폰 하루 · 폰 수정 시트)

## 1. 라칸을 넘어서는 것

라칸 코드를 읽고 찾은 빈틈이다. 이번에 전부 메운다.

| 라칸 | EZ.WORK |
|---|---|
| 일정 전체가 `kv` 문서 하나. 다른 탭이 덮어써서 두 번 날아갔고, 3-방향 합치기로 막았다 | **일정 하나 = 한 줄 + 버전**. 덮어쓰기 사고가 구조적으로 안 생긴다. 합치기 코드가 필요 없다 |
| 자정을 넘는 일정을 입력에서 막는다. 스큐 근무가 자정을 넘겨 들어오면 처리가 없다 | 끝이 다음 날이어도 된다(최대 24시간). 두 열에 나눠 그린다 |
| 종일 일정이 주간 격자에 **아예 안 보인다** | 날짜 머리 아래 **종일 줄**에 그린다 |
| 이미 만든 반복 일정의 요일·끝나는 날을 화면에서 못 바꾼다 | 수정 시트에서 반복 규칙을 바꾼다(이후 모두 / 전체) |
| 반복 회차를 '이번만'으로 고치면 지점·이동시간 변경이 **조용히 버려진다** | 예외 한 줄이 일정의 모든 칸을 덮어쓸 수 있다 |
| 이동이 앞 일정과 겹쳐도 경고가 없다 | 이동 띠 옆에 **'N분 늦음'** 표시 |
| 끌어서 옮기기가 할 일에만 있다 | 데스크톱에서 일정 끌어 옮기기·아래 끝 끌어 늘리기 (결정 4) |
| 스큐 근무를 열 때마다 브라우저가 서버 함수로 끌어온다 | 에이전트가 `schedule_sync` 로 넣는다 (4장) |
| 외출 준비 기본값이 0 이라 새 사용자는 준비가 안 붙는다 | 기본값 35 / 10 / 50 을 설정에 둔다 |

## 2. 데이터

모두 RA-KAN Supabase 안 `ez_` 접두 테이블. RLS 는 `owner = auth.uid()`. 시간은 **그 날짜의 0시부터 센 분**으로 저장한다. 한국은 일광절약시간이 없어서 날짜+분이 가장 단순하고, 반복 일정에도 맞다. 시간대는 설정에 `Asia/Seoul` 로 고정해 둔다.

### `ez_places` 지점

| 열 | 뜻 |
|---|---|
| `id`, `owner` | |
| `name` | 1~30자. 같은 사람 안에서 겹치면 안 됨 |
| `role` | `home` / `work` / `school` / null. **`home` 은 한 사람에 하나** (부분 유일 인덱스). work·school 은 여럿 가능 |
| `symbol` | 지점 심볼. 정해진 12개 중 하나(집·학사모·가방·컵·책·운동·병원·장보기·사람·건물·나무·핀). 기본은 역할에서: home=집, school=학사모, work=가방, 없음=핀 |
| `color` | 지점 색. 정해진 8개 옅은 색(하늘·보라·살구·모래·민트·분홍·청록·노랑) 중 하나, 만들 때 안 쓴 색부터 자동. 라이트·다크 값이 따로 있다 |
| `sort` | 칩 순서 |
| `deleted_at` | 지운 지점. 일정에 붙은 지점은 바로 지우지 않고 숨긴다 |

- 한 사람 지점 최대 12개
- 지점을 지우면 그 지점이 낀 이동시간은 같이 지운다. 그 지점이 붙은 일정은 지점 없음이 되지 않고 **이름은 남는다**(지운 지점도 이름은 읽을 수 있음). 동선 계산에서만 빠진다

### `ez_travel` 이동시간

| 열 | 뜻 |
|---|---|
| `owner`, `a`, `b` | 지점 두 개. `a < b` 로 저장해 방향 없음(왕복 같은 시간) |
| `minutes` | 1~600 |

- 표에 없는 쌍은 **0분으로 지어내지 않고 '모름'**. 계산은 0으로 하되, 화면 설정에서 빈칸으로 보인다

### `ez_events` 일정

| 열 | 뜻 |
|---|---|
| `id`, `owner` | |
| `title` | 1~100자 |
| `date` | 시작 날짜 (반복이면 첫 회차) |
| `start_min`, `end_min` | 0~1439 / `start_min` 초과 ~ `start_min + 1440`. **1440 을 넘으면 다음 날에 끝남**. 종일이면 둘 다 null |
| `place_id` | 지점. 없으면 동선 밖 |
| `where_text` | 상세 장소 글. 0~100자. 동선에는 안 씀 |
| `travel_min` | 이 일정만의 이동시간. 표보다 우선. 지점 없는 일정에서 주로 씀 |
| `note` | 0~2000자 |
| `repeat` | null / `{freq:'daily', until?}` / `{freq:'weekly', days:[1..7], until?}`. 1=월, 7=일. `until` 은 그날 포함 |
| `source`, `external_id` | 바깥 일정. 둘 다 null 이면 내가 만든 것. 둘 다 있거나 둘 다 없거나 (DB 제약) |
| `version` | 고칠 때마다 +1 |
| `deleted_at` | 휴지통 없음. 되돌리기(5초)용 표시 후 지운다 |
| `created_at`, `updated_at` | |

- `(owner, source, external_id)` 유일
- **바깥 일정은 사람이 못 고친다.** DB 트리거가 `source` 있는 줄을 일반 갱신에서 막고, `ez_schedule_sync` 함수만 쓴다
- weekly 인데 `days` 가 비면 거절. 라칸은 시작일 요일로 메웠는데, 조용히 메우는 것보다 거절이 낫다

### `ez_event_exceptions` 반복의 '이번만'

| 열 | 뜻 |
|---|---|
| `event_id`, `on_date` | 어느 반복 일정의 어느 회차(원래 날짜) |
| `skip` | 그 회차를 건너뜀 |
| `patch` jsonb | 그 회차만 바꾼 칸. `date`·`start_min`·`end_min`·`title`·`place_id`·`where_text`·`travel_min`·`note` 중 아무거나 |

- `on_date` 가 실제로 반복이 생기는 날이 아니면 거절
- 회차를 다른 날로 옮기면 원래 날짜에서 빠지고 옮긴 날에 그린다

### `ez_schedule_settings` 사람당 한 줄

| 열 | 기본값 |
|---|---|
| `prep_first` 첫 외출 준비 | 35 |
| `prep_again` 다시 나갈 때 준비 | 10 |
| `home_stay` 집에 들르는 최소 체류 | 50 |
| `meal_min` 식사 길이 | 40 (0 이면 식사 추천 끔) |
| `lunch` / `dinner` 창과 선호 시각 | 11:00–14:00 · 12:00 / 17:00–20:30 · 18:00 |
| `tz` | `Asia/Seoul` |

## 3. 계산 규칙

`lib/schedule/` 의 순수 함수 하나 `planDay(날짜, 그날 회차들, 지점, 이동시간, 설정, 전날에서 넘어온 상태)`. 웹과 MCP 가 같이 쓴다. 에이전트도 "내일 몇 시에 나가야 해?" 에 같은 답을 낸다. 라칸 셀프테스트의 경계값(50분이면 들름, 49분이면 안 들름 등)은 시험으로 옮긴다.

**회차 펼치기**
- 반복 + 예외 → 보는 기간의 회차 목록. 회차 id = `일정id:원래날짜`
- 종일 회차는 동선·식사 계산에서 빠진다. 종일 줄에만 그린다

**동선**
- 하루는 집에서 시작해 집에서 끝난다. 집이 정해져 있지 않으면 첫 출발·마지막 귀가·준비·집 들르기가 없고 지점 사이 이동만 센다
- 지점이 바뀌면 이동 띠. 이름은 목적지 기준: work → **출근**, school → **등교**, home → **귀가**, 그 외 → **이동**
- 이동시간: 일정의 `travel_min` > 표 > 0. 지점이 같으면 0
- 들어가는 이동은 도착(일정 시작) 직전, 나오는 이동은 앞 일정 끝 직후
- **집 들르기**: 밖에서 다음 지점까지 `다음 시작 − 앞 끝 − (귀가 + prep_again + 다시 이동) ≥ home_stay` 이면 들렀다 간다. 귀가·다시 이동 둘 다 표에 있어야 한다
- **지점 없는 일정**은 동선을 만들지 않고 직전 위치를 유지한다. `travel_min` 만 있으면 그 시간만큼 이동 띠를 그리되 위치는 안 바뀐다(라칸과 같음)
- **비키기**: 준비·이동 띠가 지점 없는 일정과 겹치면 나갈 땐 일찍, 들어올 땐 늦게 비킨다. 비킬 자리가 없으면 원래 자리에 두고 겹침으로 그린다
- **늦음**: 들어가는 이동의 출발이 앞 일정 끝보다 이르면 그 차이를 'N분 늦음' 으로 표시한다. 저장은 막지 않는다

**외출 준비**
- 집에서 밖으로 나가는 첫 출발 직전 `prep_first`, 그날 이미 한 번 나갔으면 `prep_again`
- 이동이 0분이어도 집을 나서면 준비는 붙는다

**식사**
- 그날 시간 있는 일정이 하나도 없으면 추천하지 않는다
- 점심을 먼저, 그 자리를 막은 뒤 저녁. 창 안 빈 구간마다 `len = min(meal_min, 구간)`, 20분 미만 구간은 버린다
- 시작은 선호 시각에 가깝게, 5분 단위. 원래 길이를 못 채우면 '짧게'
- 그 창에 걸친 일정 제목에 밥·식사·회식·점심·저녁·브런치·런치·디너·맛집·뒤풀이가 있으면 그 끼니는 채운 것
- 자리가 없으면 종일 줄에 '점심 틈 없음' / '저녁 틈 없음'

**자정 넘김**
- 일정은 시작 날짜에 속한다. 화면에는 두 열로 나눠 그린다
- 그 일정 뒤 귀가는 다음 날로 넘어가고, 다음 날 계산은 **넘어온 위치·시각에서** 시작한다(`전날에서 넘어온 상태`)
- 넘어온 날의 첫 외출도 '이미 나갔음' 으로 치지 않는다. 자고 나서 다시 준비하기 때문이다

**겹치는 일정**
- 저장은 막지 않는다. 화면에서 칸을 나눠 그린다(Google Calendar 와 같음)
- 동선은 시작 순서대로 따라간다

## 4. 바깥 일정 — 구멍만

- 일정마다 `source`(예: `studycube`, `univ`, `apptive`)와 `external_id`
- `schedule_sync(source, from, to, events[])` 는 그 출처의 그 기간을 **한 트랜잭션으로 갈아끼운다**. `external_id` 가 같으면 갱신, 목록에서 빠지면 삭제, 새 것은 추가. 기간 밖은 안 건드린다
- 화면에서 바깥 일정은 **읽기 전용**이고 작은 출처 글자("스터디큐브")만 붙는다. 누르면 "스터디큐브에서 온 일정입니다" 와 마지막으로 맞춘 시각
- 출처 표시 이름은 `ez_sources(owner, source, label, synced_at)` 에 둔다. sync 가 `synced_at` 을 갱신한다
- 연동 예시
  - 스큐 근무: Claude Code 예약 작업이 STUDYCUBE 근무를 읽어 sync (결정 1)
  - 대학 시간표: 학기 초 한 번. 시간표 캡처를 보고 에이전트가 weekly 반복으로 넣음
  - APPTIVE: 일정 카드를 보고 넣음
- **짚을 점**: 라칸은 열 때마다 새로 받았다. 에이전트 방식은 동기화 주기만큼 늦고, 예약 작업은 이 PC 가 켜져 있어야 돈다

## 5. MCP 도구 (4개)

도구 설명은 매번 Claude Code 컨텍스트에 실려서 개수를 줄였다. 보고서 서랍 6개와 합쳐 10개다. 지점·이동시간 설정은 화면에서만 한다(드물게 바뀜).

| 도구 | 하는 일 | 엣지 |
|---|---|---|
| `schedule_get(from, to, free_min?)` | 회차 + **계산된 준비·이동·식사·늦음** 까지. 지점 이름도 같이. `free_min` 을 주면 그 길이 이상인 **진짜 빈 시간**(동선·준비를 뺀 것)도 | 기간 최대 62일. 넘으면 오류와 나눠 부르라는 안내 |
| `schedule_save(...)` | 넣기 또는 고치기. id 가 없으면 새로. 반복 회차는 `on_date` + `scope`(`once` / `following` / `all`) | 고칠 땐 `base_version` 필수. 낡았으면 충돌 + 현재 값. 바깥 일정이면 거절. 지점은 이름으로 받고, 없는 이름이면 가까운 이름 제안 |
| `schedule_delete(id, on_date?, scope?)` | 지우기. 반복이면 scope | 바깥 일정 거절 |
| `schedule_sync(source, from, to, events[])` | 바깥 일정 갈아끼우기 | 한 번에 500개, 기간 최대 200일. 검사 실패 시 위치·이유 목록, 아무것도 안 바꿈 |

`following` 은 원래 일정의 `until` 을 그 전날로 끊고 그날부터 새 일정을 만든다. 끊는 날 이후의 예외는 새 일정으로 옮긴다(라칸은 버렸다). 첫 회차에서 `following` 이면 `all` 과 같다.

## 6. 화면

**데스크톱 — 이번 주**
- 위쪽 줄: 오늘 · ‹ › · "9월 28일 – 10월 4일" · (오른쪽) 설정 · + 새 일정 · 밝기
- 월~일 7열. 날짜 머리 → 종일 줄 → 시간 격자
- **열은 132px 까지만 넓어진다.** 블록이 쓸데없이 넓어지지 않게. 남는 폭은 오른쪽 **상세 패널**(320px~)이 쓴다. 앱 폭 1180px 미만에서는 패널을 접고 열이 폭을 나눠 쓴다
- 시간 범위는 그 주 일정·띠가 걸친 범위 ±1시간, 최소 8시간(라칸과 같음). 1시간 48px
- **색과 심볼은 일정마다 고르지 않고 지점에서 온다.** 일정 바탕 = 그 지점의 색, 제목 앞 = 그 지점의 심볼(지점 색). 지점 없는 일정 = 옅은 키위. 바깥 일정도 같은 규칙이고 출처 글자만 더 붙는다
- 출근·등교·귀가·이동 = **회색 블록 + 글자만**(심볼 없음). 준비 = 더 옅은 회색. 늦음 = 옅은 빨강. 식사 = 점선. 빗금은 쓰지 않는다
- 블록 안 여백 위아래 6px · 좌우 10px(폰 8 · 14)
- **좁아지면 말줄임 대신 덜 중요한 것부터 뺀다.** 블록 자기 폭 기준(컨테이너 쿼리)
  1. 출처 글자 (안쪽 폭 130px 이하)
  2. 끝 시각 → 시작 시각만 (92px 이하)
  3. 제목 앞 심볼 (64px 이하)
  4. 시간과 제목 → 지점 심볼만 가운데 (44px 이하). 지점 없는 일정은 제목을 남긴다
- 제목은 **띄어쓰기에서만** 줄을 바꾸고 블록 높이만큼 여러 줄. 두 줄이 안 나오는 짧은 블록은 시간을 빼고 제목에 준다
- 이동·준비 띠는 좁으면 분을 빼고 이름만("등교"), 아주 좁으면 비운다. 늦음 띠는 "10분" 은 끝까지 남긴다
- 뺀 내용은 마우스를 올리면(데스크톱) 전부 보이고, 누르면 상세가 뜬다
- 지금 선: 오늘 열에 키위 선, 시간 축에 현재 시각
- 빈 칸 누르기 → 그 시각(30분 단위)으로 새 일정 시트. 끝은 +60분
- 블록 누르기 → 상세 패널에 제목 · 시간 · 반복 · 지점 · **나갈 시각(어디서 몇 시 출발 · 이동 몇 분, 늦음)** · 메모 · 수정 · 없애기. 패널이 접힌 폭에서는 같은 내용을 블록 옆 작은 창으로
- 끌어 옮기기·아래 끝 끌어 늘리기, 15분 단위 (결정 4). 반복 회차를 끌면 놓을 때 '이번만 / 이후 모두'
- 키보드: ← → 주 이동, T 오늘, N 새 일정, Esc 닫기

**폰 — 하루** (결정 3)
- 위: ‹ 날짜 › · **하루 / 주** · 오늘. 그 아래 주간 띠(7칸, 일정 있는 날 점). 좌우로 밀면 하루씩
- **주 미니어처**: 7일을 한 화면에. 글자 없이 블록만(지점 색 + 지점 심볼, 이동·준비는 회색, 늦음은 빨강, 식사는 뺌). 7시–24시를 화면 높이에 맞춤. 날짜를 누르면 그날 하루 보기로
- 본문: 하루 세로 타임라인. 종일 줄 · 블록 · 띠 · 지금 선
- 오른쪽 아래 + 버튼
- 블록 누르기 → 바로 수정 시트. 끌기는 없다

**수정 시트** (데스크톱은 가운데 창, 폰은 아래에서 올라옴)
- 제목 · 날짜 · 시작–끝(종일 토글) · 지점 칩(지점 색 심볼 + 이름, 등록 지점 + 없음) · 반복(안 함 / 매일 / 매주 + 요일 칩, 끝나는 날) · 메모
- 상세 장소·이동시간 직접 입력은 '더보기' 아래에 둔다(드물게 씀)
- 끝이 시작보다 이르면 다음 날로 본다("다음 날 01:00" 로 표시). 24시간 넘으면 거절
- 반복 회차를 저장하면 '이번만 / 이후 모두'. 반복 규칙 자체를 바꾸면 '이번만' 은 없다
- 한글 조합 중 Enter 무시

**설정** (톱니)
- 지점: 이름, 역할(집·근무지·학교·없음), 심볼, 색, 순서
- 이동시간: 지점 쌍 표. 빈칸 = 모름
- 외출 준비 35 / 10, 집 들르기 50, 식사 40

**공통**
- 저장은 화면 먼저 바꾸고, 실패하면 되돌리고 알림
- 지우기 알림에 '되돌리기' 5초
- 다른 곳(에이전트·다른 창)에서 고쳐 버전이 안 맞으면 "방금 다른 곳에서 이 일정을 고쳤습니다" + 새로 불러오기
- 창이 다시 보일 때 그 주를 새로 읽는다
- 홈 '일정' 타일이 살아난다. 사이드바에 '일정' 이 생긴다

## 8. 데이터 옮기기

1. 라칸 `kv` 의 `plan` 문서를 **통째로 로컬 파일로 백업**한다. 에이전트가 Supabase 로 한 번 읽어 저장소 밖(`Documents/EZ.WORK 백업/`)에 둔다. ez-work 코드는 `kv` 를 읽지 않는다는 규칙을 지키기 위해서다
2. 옮기기 스크립트 `scripts/import-rakan-plan.ts` 가 그 파일을 읽어 넣는다
   - 일정 22개(반복 3), 지점 4곳, 이동시간 6쌍, 설정
   - 요일 0=일 → 7=일로 바꾼다
   - 라칸 `prepMin` 값 그대로, `prep_again = min(prepMin, 10)`
   - `color`·`important` 는 버린다(1차에 색 선택 없음). 백업 파일에는 남는다
   - `exceptions` → `ez_event_exceptions`
3. 할 일 12개는 옮기지 않는다. 백업 파일에 남겨 두고 플래너 모듈 때 쓴다 (결정 2)
4. `classOverrides` 는 버린다. 대학 시간표는 에이전트가 `univ` 로 새로 넣는다
5. 스큐 근무는 옮기지 않고 첫 sync 로 받는다
6. 옮긴 뒤 이번 주를 라칸과 나란히 열어 띠 위치가 같은지 본다. 라칸은 끄기 전까지 그대로 둔다
