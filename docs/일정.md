# 일정 — 설계서 초안 v0

> 2026-09-30. EZ.WORK 두 번째 모듈. 끝나면 배포(라칸을 끌 수 있는 조건).
> 기준: 보고서 서랍과 같은 원칙 — 규칙은 한 곳(lib·DB), 미니멀 1차, 에이전트는 MCP 로.

## 0. 정해진 것

- **핵심 두 가지**: 이번 주 시간표 · 동선·외출준비·식사 자동 계산 (라칸에서 실제로 매일 쓰는 것)
- **빠짐**: 오늘 탭, 할 일 끼워넣기·추천 (라칸에 있었지만 안 씀)
- **에이전트**: 읽기·쓰기 모두 (MCP)
- **구글 캘린더**: 연동 안 함. EZ.WORK 가 원본
- **바깥 일정**(스큐 근무·대학 시간표·동아리 등): 내장 연동을 만들지 않는다. **들어올 구멍만** 만들고, 연동은 각자 에이전트가 한다
- **폰에서도 많이 고친다** → 시간표 화면은 폰 우선
- 라칸에서 가져올 것: **규칙(동작)과 데이터**. 코드는 가져오지 않고 동작을 아래 3장에 명세로 옮겨 새로 만든다

레퍼런스: **Google Calendar 주간 보기** — 격자, 끌어 옮기기·늘리기, 반복 일정 '이번만 / 이후 모두'.

## 1. 왜 저장 방식을 바꾸나

라칸은 일정 전체가 `kv` 문서 하나였다. 열어둔 다른 탭이 옛 문서로 전체를 덮어써 일정이 날아간 일이 두 번 있었고, 3-방향 합치기로 막았다.
→ EZ.WORK 는 **일정 하나 = 한 줄**. 보고서 서랍처럼 버전으로 동시 수정을 잡는다. 덮어쓰기 사고가 구조적으로 안 생긴다.

## 2. 데이터 (초안)

| 테이블 | 담는 것 |
|---|---|
| `ez_places` | 지점: 이름, 역할(`home` / `work` / `school` / 없음) |
| `ez_travel` | 두 지점 사이 이동시간(분). 순서 없는 쌍 |
| `ez_events` | 제목, 날짜, 시작·끝(분) 또는 종일, 지점 + 상세 장소, 일회성 이동시간, 메모, 반복(매일 / 매주 요일들, 끝나는 날), 색, **출처**(`source`, 없으면 내가 만든 것), **바깥 id**(`external_id`), version |
| `ez_event_exceptions` | 반복 일정의 '이번만' — 그날 건너뜀 / 그날만 시간·장소 바꿈 |
| `ez_schedule_settings` | 외출 준비(35분), 식사 길이(40분), 하루 시작·끝 등. 사람 하나당 한 줄 |

## 3. 옮겨올 규칙 (라칸 동작 → 명세)

계산은 `lib` 순수 함수 하나로. 웹과 MCP 가 같이 쓴다(에이전트도 "내일 몇 시에 나가야 해?"에 답할 수 있게).

**동선**
- 하루는 집에서 시작해 집에서 끝난다. 집이 정해져 있지 않으면 왕복을 세지 않는다
- 지점이 바뀌면 이동 블록. 이름표: 근무지로 → **출근**, 학교로 → **등교**, 집으로 → **귀가**, 그 외 → **이동**
- 이동시간 표에 없는 쌍은 0 (지어내지 않는다). 일회성 일정에 직접 적은 이동시간이 표보다 우선
- **집 들르기**: 밖에서 다음 일정까지, 귀가 + 다시 준비 + 다시 출발을 빼고도 집에 **50분 이상** 있을 수 있으면 들렀다 간다
- 지점 없는 일정은 동선을 만들지 않고 직전 위치를 유지. 대신 준비·이동과 겹치면 준비·이동이 비켜 간다(나갈 땐 일찍, 들어올 땐 늦게). 비킬 자리가 없으면 그대로 두고 겹침으로 표시

**외출 준비**
- 집에서 나갈 때 출발 직전 **35분**
- 그날 이미 한 번 나갔다가 다시 나갈 땐 **10분**

**식사**
- 점심 11:00–14:00 (12:00 선호), 저녁 17:00–20:30 (18:00 선호), **40분**
- 고정 일정이 아니라 빈 곳에 떠 있는 추천(점선). 들어갈 자리가 없으면 "먹을 틈 없음" 표시
- 그 시간대 일정 제목에 밥·식사·회식·점심·저녁·브런치·런치·디너·맛집·뒤풀이가 있으면 그 끼니는 채운 것으로

## 4. 바깥 일정 — 구멍만 만든다

- 일정마다 `source`(예: `studycube`, `univ`, `apptive`)와 `external_id`
- MCP `schedule_sync(source, from, to, events[])` — 그 출처의 그 기간 일정을 **한 번에 갈아끼운다**(한 트랜잭션). `external_id` 가 같은 건 갱신, 없어진 건 삭제, 새 건 추가
- 화면: 바깥 일정은 **읽기 전용** + 작은 출처 표시("스터디큐브"). 고치려면 원본에서
- 연동은 에이전트 몫. 예:
  - 스큐 근무표 → Claude Code 예약 작업으로 매일 아침 동기화
  - 대학 시간표 → 학기 초 한 번, 시간표 캡처를 보고 에이전트가 넣음
  - APPTIVE → 일정 카드를 보고 넣음
- **짚을 점**: 라칸은 페이지를 열 때마다 스큐 근무를 새로 끌어왔다. 에이전트 방식은 동기화 주기만큼 늦다

## 5. 화면 — 이번 주 시간표

- 월~일 격자: 일정 블록 · 이동/준비 띠 · 식사 추천(점선) · 지금 선
- 빈 칸 누르기 → 새 일정 / 블록 누르기 → 상세·수정 / 반복 일정은 '이번만 · 이후 모두'
- 데스크톱: 끌어서 옮기기, 아래 끝 끌어서 늘리기
- 폰: 모양 미정(아래 질문)
- 설정: 지점 · 이동시간 · 집/근무지/학교 · 외출 준비 시간

## 6. MCP 도구 (초안, 6개)

| 도구 | 하는 일 |
|---|---|
| `schedule_get(from, to)` | 일정 + **계산된 이동·준비·식사** 까지 |
| `schedule_add(...)` | 일정 넣기 |
| `schedule_update(id, scope, ...)` | 고치기. 반복은 `once` / `following` |
| `schedule_delete(id, scope)` | 지우기 |
| `schedule_free(from, to, minutes)` | 빈 시간 찾기 (추천·점수 없이, 동선·준비를 뺀 진짜 빈 시간만) |
| `schedule_sync(source, from, to, events[])` | 바깥 일정 갈아끼우기 |

- 라칸 `kv` 의 `plan`: 일정 22개(반복 3), 지점 4곳, 이동시간 6쌍, 설정 → 새 테이블로
- **할 일 12개**: 미정(아래 질문)
- 대학 수업 한 회차 옮김 기록(`classOverrides`): 대학 시간표를 에이전트가 새로 넣으면 필요 없음
