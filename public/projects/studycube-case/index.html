Design Decisions

왜 이렇게 만들었나

기능이 아니라 결정의 기록. 각 결정 뒤에는 실제로 겪은 제약과 트레이드오프가 있다.

01

출결 = 불변 이벤트 로그

attendance_event(kind: in|out, at)를 append-only로 쌓는다. 상태를 수정하지 않고 이벤트만 추가한다.
상태 토글로 만들면 "언제"가 사라지고 정정 흔적도 안 남는다. 삭제는 마지막 이벤트 취소만 허용한다.
02

벌점 점수는 스냅샷

기록 시점의 점수를 행에 그대로 저장한다. 프리셋 규칙표를 참조하지 않는다.
과거 불변성 확보. 나중에 프리셋을 바꿔도 지난 집계가 흔들리지 않는다. 누적은 내역 합산, 정정은 해당 내역 삭제로 — 별도 차감 항목은 없앴다.
03

순찰 기록은 좌석 스냅샷

patrol_event.seat_id에 당시 좌석 번호를 그대로 저장한다.
학생이 자리를 옮겨도 순찰 이력을 재현하면 당시 배치 그대로 나온다. 현재 좌석을 역참조하지 않는다.
04

정적 우선 원칙

회비·지각 기준·벌점 프리셋을 설정 UI가 아니라 코드 상수로 고정한다.
단일 지점, 규칙이 거의 안 바뀐다 — 옵션 화면은 비용만 크다. 다만 branch_id는 스키마에 심어 다지점 확장 여지는 남겼다.
05

상태 모델 축소

학생 상태를 재원 · 휴원 2개로 좁혔다(퇴원 상태 폐지).
자주 안 쓰는 조작은 메인 화면에서 빼고 우클릭(터치는 long-press) 컨텍스트 메뉴로 옮겼다. 주 화면은 매일 쓰는 것만.
06

공개 폼 인증 = 이름 + 5자리 코드

전화번호가 없는 학생도 커버해야 해서 이름과 5자리 코드로 인증한다. DB 테이블 기반 레이트리밋을 붙였다.
4자리는 생일(MMDD)이 연상돼 5자리로. 서버리스라 인메모리 카운터를 못 쓰므로, DB에 15분 창 10회 실패 잠금을 구현 — 잠긴 이름은 정답 코드도 차단한다.
Data

운영 데이터 추이

4주치 더미 데이터를 시드 고정 PRNG로 생성했다 — 새로고침해도 같은 그래프가 나온다. 평일 출석률 78~92%, 토요일은 낮고 일요일은 휴무, 시험 직전 주(3주차)엔 출석이 오르고 벌점이 줄어드는 현실적 패턴을 반영했다.

Debugging Log

실제로 부딪힌 것들

증상 → 원인 → 수정 → 배운 것. 실제로 마주친 버그와 그 정정 기록이다.

01"11"을 치면 "01"이 되는 입력창
증상

시간·번호 입력 중 두 자리를 입력하면 앞자리가 사라지고 0으로 패딩됐다.

원인

onChange 핸들러 안에서 zero-padding 정규화를 즉시 실행하고 있었다.

수정

입력 중에는 raw 문자열을 그대로 유지하고, 정규화는 blur 시점에만 수행하도록 분리했다.

배운 것

입력은 raw 유지, 정규화는 blur — 이후 모든 폼 입력의 원칙으로 확립.

02순찰 이력 화면의 레이스 컨디션
증상

세션 A를 보다가 B로 빠르게 전환하면, 늦게 도착한 A의 응답이 B 화면을 덮어썼다.

원인

비동기 요청 완료 순서가 요청 순서와 다를 수 있는데 이를 검증하지 않았다.

수정

요청 시점의 세션 id를 ref에 저장하고, 응답 도착 시 현재 선택된 세션과 대조한 뒤에만 상태를 반영했다.

배운 것

비동기 응답은 도착 순서를 신뢰하지 않는다 — 항상 "지금도 유효한 요청인가"를 확인.

03좌석 컴포넌트 플리커
증상

좌석 하나만 갱신돼도 배치도 전체가 깜빡였다.

원인

좌석 컴포넌트를 부모의 render 함수 본문 안에서 선언 — 매 렌더마다 새 함수 취급되어 전체가 remount됐다.

수정

컴포넌트 정의를 모듈 최상위로 끌어올렸다.

배운 것

컴포넌트는 항상 모듈 스코프에서 선언 — render 안에서 컴포넌트를 만들지 않는다.

04대시보드 합계 ≠ 목록 합계
증상

대시보드, 좌석 배치도, 학생 목록의 총원 숫자가 서로 달랐다.

원인

집계 쿼리마다 휴원생 필터링 기준이 달라, 화면마다 다른 조건으로 학생을 세고 있었다.

수정

모든 집계를 "재원생 join" 하나로 통일해 세 화면이 항상 같은 숫자를 참조하도록 했다.

배운 것

같은 개념(총원)은 코드베이스 전체에서 단 하나의 쿼리 정의만 가져야 한다.

05서버 컴포넌트가 클라이언트 헬퍼를 import해 빌드 붕괴
증상

배포 빌드가 알 수 없는 이유로 실패, 로컬에서는 재현되지 않았다.

원인

서버 컴포넌트가 'use client' 지시어가 붙은 파일의 순수 함수를 import하고 있었다.

수정

공용 순수 함수를 지시어 없는 별도 util 파일로 분리했다.

배운 것

서버 · 클라이언트 어디서든 재사용할 유틸은 처음부터 경계 없는 파일에 둔다.

Architecture

아키텍처 한 장

세 개의 진입점이 하나의 Supabase를 공유한다.

멀티테넌트 — 모든 테이블 코어에 branch_id를 심어, 지점이 늘어도 스키마를 안 바꾼다.
권한은 역할이 아니라 capability 판정 — "이 사람이 이 동작을 할 수 있는가"를 매번 함수로 묻는다.
모듈 레지스트리로 화면을 등록해 증설 — 새 모듈을 추가해도 라우팅·권한 체계를 다시 짜지 않는다.
