7장 데이터 정제와 병합
더러운 데이터를 다듬고(정제), 흩어진 표를 키로 합친다(병합).
질문 지도
왜 분석 전에 데이터를 손봐야 하고, 두 표는 어떻게 하나로 합치는가?

현실 데이터에는 빈칸(결측치), 말도 안 되는 값(이상치), 제각각 표기(형식 불일치)가 섞여 있다. 이걸 그대로 분석하면 평균 하나가 통째로 망가진다. 데이터 과학자가 업무 시간의 80%를 정제에 쓰는 이유다.

그리고 현실의 정보는 한 표에 다 들어 있지 않다. 고객 표 따로, 주문 표 따로. 이 둘을 공통 키로 이어붙이는 것이 병합이다.

지금 위치 → 데이터를 "신뢰할 수 있는 형태"로 만든 뒤, 여러 표를 합쳐 분석 준비를 끝낸다.
먼저 알 단어
결측치 NaN
값이 비어 있는 칸. NaN = Not a Number. 응답 누락 등으로 생긴 공백.
이상치
정상 범위를 크게 벗어난 값. 과거 결측코드 -999 같은 게 끼면 통계를 파괴한다.
정제(Cleaning)
결측·이상·형식 문제를 바로잡아 분석 가능한 형태로 만드는 작업.
병합(Merge)
여러 데이터프레임을 공통 키(Key) 기준으로 결합하는 것.
키(Key)
두 표를 합칠 때 기준이 되는 같은 컬럼(예: 고객ID).

1. 데이터 품질을 망치는 4가지

현실 데이터가 더러운 이유는 크게 네 가지다. 두문자로 "결-이-형-텍"으로 외우면 객관식·단답에 강하다.

문제영문뜻 / 예시
① 결측치Missing Values응답 누락으로 생긴 빈칸. NaN
② 이상치·오류코드Outliers & Codes비정상 값. 과거 결측코드 -999 방치
③ 형식 불일치Format Inconsistency같은 정보 다른 표기 → 병합 실패. 010-1234-5678 vs 01012345678
④ 텍스트 품질Text Quality대소문자·공백 차이로 중복. John Kim / JOHN KIM

2. 이상치는 왜 중앙값으로 메우나

점수 [85, 92, -999, 78]의 평균은 (85+92-999+78)/4 = -186이다. 멀쩡한 세 값 사이에 낀 -999 하나가 평균을 음수로 끌어내린다. 이게 이상치의 파괴력이다.

개념대체값으로는 중앙값(median)을 쓴다. 평균은 극단값에 크게 흔들리지만, 중앙값은 "가운데 값"이라 이상치에 둔감하기 때문이다.

그래서 0~100 범위를 벗어난 점수를 중앙값으로 갈아끼운다. 결측치 행을 통째로 빼려면 df.dropna(), 값별 개수를 세려면 df['성별'].value_counts()(내림차순 반환)를 쓴다.

def clean_invalid_scores(df):
    if '점수' in df.columns:               # 컬럼 존재 확인(방어적)
        median_score = df['점수'].median()    # 중앙값
        df['점수'] = df['점수'].apply(
            lambda x: median_score if (x < 0 or x > 100) else x)
    return df

형식 통일(예: 흩어진 성별 표기)은 매핑 딕셔너리로 한 번에 바꾸고, 매핑에 없는 값은 원래대로 둔다.

gender_map = {'M':'남', 'Male':'남', '1':'남', 'F':'여', '2':'여'}
df['성별'] = df['성별'].astype(str).str.strip()        # 문자열화+공백제거
df['성별'] = df['성별'].map(gender_map).fillna(df['성별'])  # 통일, 없으면 원본 유지

3. 데이터 병합 — pd.merge와 네 가지 조인 ★

병합은 여러 데이터프레임을 공통 키 기준으로 결합하는 기술이다. 핵심 함수는 단 하나, pd.merge. 그리고 알아야 할 인자도 단 두 개다.

  • on='고객ID' — 무엇을 기준으로 합칠지(공통 키)
  • how=... — 어떤 방식으로 합칠지(아래 4가지)

네 가지 조인은 두 집합(왼쪽 표·오른쪽 표)을 어떻게 합치느냐의 차이다. 특히 inner(교집합)와 outer(합집합)를 먼저 외워라.

how 값집합남는 것대표 용도
'inner'교집합양쪽 모두 있는 행만일치 데이터만 분석
'left'왼쪽 전체df1 전부 + 매칭되는 df2주문 없는 고객 찾기
'right'오른쪽 전체df2 전부 + 매칭되는 df1고객정보 누락 탐지
'outer'합집합양쪽 모든 행(빈칸은 NaN)데이터 품질 점검
def join_files(df1, df2, join_type):
    if '고객ID' not in df1.columns or '고객ID' not in df2.columns:
        st.error("두 파일 모두에 '고객ID' 컬럼이 있어야 합니다."); return None
    return pd.merge(df1, df2, on='고객ID', how=join_type)
함정슬라이드의 실제 코드는 전부 pd.merge()다. "조인을 수행하는 pandas 함수는?"의 답은 merge. how에 들어가는 값은 따옴표 붙은 문자열 'inner' 'left' 'right' 'outer'.

1. HTML 구조 — 무엇이 화면에 보이나 ★

HTML은 부모-자식 관계의 트리 구조다. 최상위 <html> 안에 <head>와 <body> 두 형제가 들어 있다.

<html>                    문서 전체를 감싸는 최상위 뼈대
  <head>                  화면에 안 보이는 설정(제목·스타일·메타)
    <title>페이지 제목</title>
  </head>
  <body>                  ★ 실제 화면에 보이는 콘텐츠 (크롤링 주 대상)
    <h1>AI가 바꾸는 미래</h1>
    <span>작성자: 홍길동</span>
  </body>
</html>
정답"HTML 구조에서 실제 화면에 표시되는 부분 태그는?" → <body>. <head>는 제목·스타일·메타데이터 같은 안 보이는 설정, <html>은 전체 껍데기. 눈에 보이는 글·이미지는 전부 body 안에 있다.

주요 태그와 속성도 자주 묻는다.

태그뜻속성뜻

2. 정적 vs 동적, 그리고 매너

정적(Static) 페이지는 완성된 HTML을 그대로 보내준다(예: 위키백과) — 수집이 쉽다. 동적(Dynamic) 페이지는 JavaScript로 나중에 콘텐츠를 채워서, 처음 받은 HTML엔 데이터가 없어 수집이 더 복잡하다.

수집 전엔 robots.txt로 허용 범위를 확인하고(User-agent·Disallow·Allow), 서버에 부담을 주지 않도록 time.sleep()으로 간격을 둔다(매너 크롤링).

3. 크롤링 핵심 코드

import requests
from bs4 import BeautifulSoup

headers = {'User-Agent': 'Mozilla/5.0'}            # 봇 차단 방지(브라우저 위장)
resp = requests.get(url, headers=headers, timeout=8)  # timeout=무한대기 방지

soup = BeautifulSoup(resp.text, 'html.parser')
tags = soup.find_all('p')                          # 모든 <p>를 리스트로
texts = [t.get_text(strip=True) for t in tags]      # 텍스트만(공백 제거)

find_all('태그')는 조건에 맞는 모든 태그를 리스트로 반환하고, get_text(strip=True)는 텍스트만 뽑아 앞뒤 공백을 제거한다. 가격 £51.77에서 숫자만 빼려면 정규표현식 re.search(r"[\d\.]+", text)를 쓴다(\d=숫자, \.=점, +=하나 이상).

2. XML 문서 구조 — 4요소 ★

XML(eXtensible Markup Language)은 데이터를 태그로 감싸, 부모-자식으로 중첩한 트리(계층) 구조다. 구조는 네 부분으로 정해져 있다.

<?xml version="1.0" encoding="UTF-8"?>     ← ① 선언부
<사용자목록>                           ← ② 루트 요소(딱 하나)
  <사용자 id="1">                    id="1" ← ④ 속성
    <이름>홍길동</이름>               ← ③ 요소: <태그>내용</태그>
    <나이>30</나이>
  </사용자>
</사용자목록>
요소역할
① 선언부 (Declaration)최상단 <?xml … ?>. 버전·인코딩(UTF-8) 등 파일 정보 지정
② 루트 요소 (Root)모든 데이터를 감싸는 최상위 뼈대(하나만)
③ 요소 (Element)<태그>내용</태그>. 데이터를 담는 기본 단위
④ 속성 (Attribute)태그 내부의 부가 정보. 예: id="1"
정답"XML에서 파일 정보 등을 표시하는 부분 이름은?" → 선언부(Declaration). <?xml version="1.0" encoding="UTF-8"?>가 버전·인코딩 같은 파일 정보를 지정한다. (실제 데이터는 ③요소, 부가정보는 ④속성)

3. CSV vs XML, 그리고 파싱

CSV는 쉼표로 구분한 간결한 표라 읽고 쓰기 쉽고, XML은 태그로 의미가 명확해 복잡한 계층 데이터에 적합하다.

import xml.etree.ElementTree as ET
root = ET.fromstring(xml_text)       # 문자열 XML → 트리 객체
for row in root.iter("row"):          # <row> 전부 순회
    name = row.findtext("PEI_NM")   # 자식 태그의 텍스트

CSV는 pd.read_csv(file, skiprows=5, encoding='utf-8')로 읽되, 한글 공공 파일은 utf-8 실패 시 cp949로 재시도한다. OPEN API URL은 …/인증키/xml/서비스명/시작/종료/ 형태이며, 한 번에 최대 1,000개까지 호출된다(전체 25,418건이어도 1회 결과는 1,000건).

3. 5수 요약과 IQR

5수 요약은 분포를 다섯 숫자(최솟값·Q1·중앙값·Q3·최댓값)로 요약해, 평균이 못 보여주는 격차를 드러낸다. IQR(Q3 − Q1)로는 이상치를 판정한다.

IQR 이상치 경계x < Q1 − 1.5·IQR  또는  x > Q3 + 1.5·IQR

코드로는 그룹별로 묶어(groupby) 사분위를 구한다. 회귀 직선은 np.polyfit(x, y, 1)이 (기울기, 절편) 순서로 돌려준다.

for cls, g in df.groupby("class"):       # 반 기준 그룹화
    s = g["english"].dropna()           # 결측 제거
    q1, q3 = s.quantile(0.25), s.quantile(0.75)   # Q1, Q3
    lo, mid, hi = s.min(), s.median(), s.max()
결과 예측두 회사 평균연봉이 둘 다 5070인데 표준편차가 다르면(A<B) 한 곳은 선형·다른 곳은 계단형. A·B반 영어 평균이 둘 다 50점이어도 한 반은 중앙 밀집, 다른 반은 하위 밀집+이상치. "평균이 같다 ≠ 같은 데이터"가 정답 방향이다.

2. 심슨의 역설

각 하위집단에서는 한쪽이 우세한데, 전체로 합치면 결론이 정반대로 뒤집히는 현상이다. 원인은 결과에 영향을 주는 숨겨진 변수가 두 집단에 불균등하게 배정되는 것.

실습 데이터에서, 남성은 합격이 쉬운 A학과에, 여성은 어려운 B학과에 몰려 지원했다.

학과남성 합격률여성 합격률
A (쉬움)80%90%
B (어려움)30%35%
전체70%46%

학과별로는 여성이 모두 높은데, 전체로 합치면 남성(70%) > 여성(46%)으로 역전된다. 여성이 합격률 낮은 B학과(어려움)에 대거 지원했기 때문이다. 난이도라는 숨은 변수의 불균등 배정이 만든 착시다.

대응전체 평균만 맹신하지 말고, 하위집단 성과를 구성비와 함께 교차 점검한다. 설계 시 무작위 배정, 분석 시 하위집단 분리·가중치 보정.
